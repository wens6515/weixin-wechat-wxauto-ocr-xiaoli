# v2.9.0「语音发送」更新记录

## 新功能

### 语音发送（音源接口化）

- 小漓会发微信语音条了。**音源接口化**：小漓不内置任何语音模型——只做 TTS 服务的 HTTP 客户端，模型/权重/参考音频全部在用户自己部署的服务端（如 GPT-SoVITS api_v2），出厂不带任何音色，端点与「音色档案」在设置页配置
- **音色档案**：每行一份参考音频（3~10 秒、清晰人声）+ 逐字对应的文本稿；「通用」行必填（默认音色），其余行是**情绪参考**（开心/生气/吃惊……）——配了哪些键，AI 可选的情绪就是哪些，不硬编码任何模型包的情绪集
- **语音模式三态**（设置页开关，保存即热生效）：
  - 关闭：语音链路整体不激活（模型根本不知道有语音能力）
  - 模型自主：AI 按语境决定何时发语音（对方要求语音/念东西等明确语境才调 send_voice 工具），并按语境挑情绪
  - 始终语音：AI 的每一条回复都必须经 send_voice 发出（工具为强制回复通道，双重纪律：system 纪律消息 + 工具描述），每条都按语境挑情绪
- 参考音频路径是 **TTS 服务器那台机器上的路径**（单机部署即本机路径）；情绪参考合成失败自动退「通用」重试一次，再失败回退文本

### 发送链路（真机验证）

- 路由：TTS 合成 wav → VB-CABLE 虚拟声卡 → 微信录音触发 → 语音条发出
- 微信录音触发用 **SendInput 物理级右 Alt**（扩展键标志 + 扫描码——Qt 程序不认 pyautogui 的裸按键），按住后以输入区绿色「松开发送」胶囊的像素检测确认录音已触发，未触发立即松开中止
- **持久渲染流**：进程内常开一条输出流「桥保温」，环回质检与正式发送共用同一条流——「播一遍即关」的冷流模式环回质检会随机死零（实测），持久流一次过闸
- **环回质检闸门**：正式发送前经虚拟声卡自采一遍音频，电平达到人声量级才放行——采不到信号绝不发送，宁可回退文本不发静音；采样率按候选表动态试开，不写死
- **默认录音设备自动切换/恢复**：发送前把三个 role 的默认录音设备切到 CABLE Output（IPolicyConfig，逐一回读校验），发送完恢复用户的真实麦克风——不恢复等于用户麦克风失效
- 发送前先切目标会话并读标题复验，确认不了不发送（防发错人，与触发式发送同一防线）；群聊同样可发语音
- **fail-closed 全链路**：端点不可达/合成失败/单段超上限/质检不过/设备切换未确认/胶囊未出现——任一环节失败自动回退文本回复，回复永不丢
- 长回复按分段逐条发语音（段间无额外间隔——语音条自带节奏），单段合成超 55 秒（微信语音条 60 秒硬上限前的保险丝，可配）整条回退文本
- VB-CABLE 只做一次性检测（未安装时语音回退文本并提示），不要求用户改任何系统设置

### 颜文字不再读成乱语

- 症状：回复里的颜文字（如 `(｡･ω･｡)`）被 TTS 读成怪词（真机实测读出「欧米奇」）
- 修复：语音合成前剥掉读不出人话的装饰——只有符号/生僻字母的括号段（颜文字）、emoji、假名/希腊字母等颜文字专用字符类；含汉字或字母数字的括号是真内容，保留（（真心话）、(20分钟)、(OK)）。剥除只作用于合成输入：**记忆与文本回复里的颜文字原样保留**；整条剥完为空（纯颜文字回复）→ 原文回退文本，让对方至少「看」得到表情

### 语音内容以纯文本写记忆

- 发过语音后，记忆里存的是那句话的原文（不加 [语音] 之类标记）——AI 记得「说了什么」，不关心「用什么形式说的」

## 优化

### 文本分段的「对方正在输入」节奏

- 多段文本回复的段间 2 秒，从「上一条发送后」移到「**下一条粘贴进输入框后、回车前**」——对方端在这段停留里看到「对方正在输入…」，多条消息有活人感；首段前不停

### 设置页功能开关区

- 新增功能开关，全部保存即热生效：**语音发送**（三态）、**联网搜索**（关闭后 AI 无法自主搜索/抓取网页）、**任务桥**（关闭后一切消息走普通聊天/文件识别，不投天枢）、**状态监视**（原开关保留）
- 关闭的实现是「工具不声明」：模型看不到工具就不会调用，不做运行时拦截

## 升级注意

- **语音默认关闭**：要在设置页「语音发送」组配置 TTS 端点与音色档案后开启，部署指引见该组的引导文案
- 语音发送需要 **VB-CABLE 虚拟声卡**（免费）：已安装则自动使用；未安装时语音回退文本，不影响其他功能
- 发语音的几秒内小漓会操作微信窗口与默认录音设备（发送完自动恢复）——期间请勿手动操作微信
- 不想用语音的用户一切照旧：默认关闭，模型连 send_voice 工具都看不到
- 配置无破坏性变更，覆盖安装即可；历史记忆、任务目录、定时提醒、用量统计、角色卡都不受影响
