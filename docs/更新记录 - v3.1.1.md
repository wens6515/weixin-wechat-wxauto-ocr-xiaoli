# v3.1.1「首启引导 · 画面标定 · 天枢配置引导」更新记录

> 一句话主线：把「新用户第一次怎么用起来」补完整——首启引导两步化（目录 + **微信
> 画面标定**）；微信窗口只固定大小、**不再自动挪位置**；任务桥首次开启**引导配置
> 天枢 CLI**；升级用户给一次性标定提示；微信没开时主动提醒。

## 首启引导第二步：微信画面标定

- 新增**应用内画面标定**：截图微信窗口作底图，拖两个框——**会话列表**（左）与
  **聊天区**（右，含标题带）——聊天区顶部一条**可拖分隔线**把标题带切出来；保存
  由后端派生出运行时需要的三个区域（列表 / 标题 / 消息），热路径语义不变
- **预填 + 一键确认**：未标定用户看到的是当前生效区域（内置默认或上次标定）画好
  的框，窗口布局标准的话直接「保存并验证」即可，零拖拽
- **保存前即时试读验证**：现场读一帧，展示三个探针——会话标题（含群聊人数）/ 列表
  前几个会话名 / 最近一条消息，让用户当场确认标定有效
- **热生效**：运行中重标不需要重启引擎
- 入口三处：首启引导第 2 步（可跳过，稍后可在设置页补）、设置页新增「画面标定」
  卡片与导航项、升级用户的一次性提示
- 修复：标定配置路径改为**冻结感知**——旧实现的路径推导在安装版里指向不存在的
  目录，安装版此前从未读到过用户标定（一直跑内置默认比例）；打包保留清单补上
  `wx_ocr_region.json`，重打测试区不再清掉用户标定

## 微信窗口：只固定大小，不再自动挪位置

- 删除「初始化自动把微信窗口摆到屏幕右半边」——**位置完全由用户自己摆**，程序一
  概不移动
- 新增**固定窗口大小**（设置页「画面标定」卡片）：宽 × 高输入 +「读取当前」（一键
  填入当前微信窗口尺寸）+「保存并应用」（立即改大小，不重启）；初始化时自动套用；
  两个框留空 = 不调整
- 尺寸按「可见内容」语义套用（自动外扩 Windows 不可见边框），与手动拖窗口的系统
  行为一致；范围夹取防手滑，超出屏幕按屏幕尺寸收敛
- 旧配置 `wechat_window_rect`（含位置）一次性迁移：只取尺寸部分，旧键消失

## 天枢配置引导（任务桥首次开启）

- 任务桥开关第一次打开时自动弹出引导：检测 CLI（缺 → 一键安装带进度条）→
  「打开天枢 CLI」→ 在窗口里选模型、输 API key、回车确认 → 「我已配置完成」→
  自动发**首轮提示词**（任务桥协议）+ `/yes` 开全自动模式（持久化）→ 关闭 CLI
  窗口 → 标记完成，之后不再打扰
- 设置页「任务桥」卡片新增「天枢配置引导」按钮，随时可重跑；弹窗有「稍后再说」
  出口（并提示：桥开着但天枢没配好时任务会被投递但没人处理）
- **新装默认关任务桥**（首启引导写入；老配置显式设过的不动）——天枢没配好前开着，
  模型会投递注定失败的任务

## 升级用户与异常场景的保险

- **升级用户一次性标定提示**：检测到没有可用标定配置且从未提示过 → 启动时弹一次
  「建议完成一次画面标定」（新用户走首启第 2 步，不弹；打开过标定界面即标记已提示，
  不会重复打扰）
- **微信没开保险**：标定/验证时区分两种成因——「微信没开」与「进程在但还没登录完」
  （登录界面阶段没有主窗口）——给不同的下一步指引，弹窗内以醒目警告块呈现；启动时
  环境检查发现没有微信窗口也会主动提醒
- 修复：`tasklist` 输出是控制台 OEM 编码（中文系统 GBK），旧实现按文本解码会抛
  `UnicodeDecodeError` 导致环境检查误报「进程检测失败」——改字节匹配（只找 ASCII
  进程名），与编码无关

## 其他修复与清理

- `_switch_chat` 坐标缺失时直接现读列表区定位，不再先跑一次整窗 OCR 重建缓存
  （触发式发送少等约 1.2 秒）；连带清理了从未生效过的红圈坐标死通道
- 修复浏览器开发预览（mock 模式）整套失效：mock 对象初始化期自引用触发 TDZ，真窗口
  不受影响
- 文档清理：源码运行段不再引用已不存在的标定/窗口工具，工具目录清单对齐现实
