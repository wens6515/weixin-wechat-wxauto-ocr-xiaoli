# 更新记录 v2.1.0

## 核心修复

- **角色卡人设注入 system 消息**：修复单模型化后 vision 单调用分流丢失角色卡人设的问题——`call_vision_api` 现在发一条 system 消息承载角色卡 `system_prompt`（人设贴脸），路由指令 + 用户消息 + 图片仍放 user 消息。闲聊回复重新遵守角色卡设定（不用 emoji、用颜文字、不自称「微信机器人」）。
- **vision 分流注入群聊 sender**：修复群聊消息发送者信息丢失的问题——`_vision_route` 拼 prompt 时用对齐 `call_chat_ai` 的群聊/私聊三分支（群聊带发送者名、多发送者只包群名不重包、私聊带发送者），AI 现在知道是谁发的消息；`memory.json` 历史记录也保留发送者上下文。
- **单模型配置收敛**：视觉识别 / 任务判断统一走 `chat_model`，删除独立的 `vision_model` / `classify_model`（运行时从 `chat_model` 派生）。

## 说明

- 模型选择统一在「模型页」编辑，写回角色卡 `chat_model` 字段；发送图片需选用支持视觉输入的模型（如 `deepseek-v4-flash-vision-exp`）。
- 消息处理主循环架构图已更新，见 README 顶部 flowchart。

## 已知边界

- `vision-exp` 模型与 `tools`（函数调用）+ `tool_choice=auto` 组合的真实 API 行为未做端到端冒烟实测（代码级自洽 + 单测覆盖，纯文字群聊/私聊场景已由用户实测通过）。
