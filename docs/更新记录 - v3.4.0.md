# 更新记录 · v3.4.0「任意分辨率与缩放」

## 跨缩放 / 跨分辨率适配（本版核心）

此前全部像素判据（三区域、头像检测、气泡/媒体/文件卡片判定、红圈面积、语音胶囊）都按「2560×1600 + 175% 缩放」的微信窗口逐像素标定：换分辨率或缩放，界面元素随之变大变小，判据整体失准——轻则读错消息，重则一条都读不到。本版把判据改成跨档位口径：

- **逻辑像素模型**：微信界面布局按逻辑像素固定，元素物理尺寸 = 逻辑值 × 系统缩放。全部判据以 175% 标定值为基准做 ×k 换算（k = 当前缩放 / 175）：长度 ×k、面积 ×k²，颜色与比例不变；
- **窗口恒为工作区右半屏**：只钉尺寸不钉位置（移出屏幕才救援），跨档位物理尺寸一致；
- **动态分界列实测**：窗口逻辑宽不足时微信会压缩会话列（200% 档半屏窗口实测），新增「列表↔聊天空谷」扫描在窗口尺寸变化时实测分界列、覆盖静态锚（扫不出回退静态锚）——任意分辨率/缩放组合下三区域都落在正确位置；
- **头像检测抗侵蚀**：低档位下简笔画头像的细线被抗锯齿侵蚀（100% 档强像素核仅占头像高度约 53%），段扫描允许小缺口并回同段、高度闸按核占比放宽；被滚动裁断的半截头像改由显式截断保护丢弃（不漏读历史、也不读半条）；
- **锚定容差物理下限**：面板顶与头像核顶的偏差（图形内边距 + 侵蚀）不随档位等比缩小，容差加 10 物理px 下限——修复低档位两张文件卡片互相错认领（文件名被当发送者名吞掉、撤回流黏进消息）；
- **不再拦截非 175%**：连接时读取当前档位并按 k 换算，首页「显示缩放」检测卡有读数即绿，诊断文案同步调整。

真机验证（读消息全类型：文字 / 图片 / 文件 / 撤回行丢弃）：
**2560×1600 的 100% / 125% / 150% / 175% / 200%**、**1920×1080 的 100% / 125%**。
低档位 OCR 小字表现正常（100% 档 xlsx 后缀反而比 125% 识别更准）。

> ⚠️ 本版起判据自适应各种 DPI 与缩放，但跨缩放是首次全量落地：**部分分辨率/缩放组合可能仍存在未覆盖的 bug**（读不到、读错）。遇到问题欢迎在 Issues 反馈，附上系统分辨率 + 缩放比例 + 出错截图。

## 引用判型改按格式规则

引用文件不再依赖扩展名正则（150% 档 OCR 把 `.xlsx` 读成 `.xIsx` 导致误判成引用图片、还误点类型图标）：改为按「发送人：简笔画图标 + 文件名文字 + 类型图标」的格式判断——

- 几何主信号：冒号后的正文行与内容物框 x 不相交（缩略图内的文字不算文件名）；
- 并联宽松文件名 token，兜住冒号被 OCR 吃掉/后缀读花的残缺形态；
- 内容物框内的 OCR 行一律不进标注（缩略图内嵌文字、Excel 图标字形都不污染）；
- 找不到被引用的文件时带 `[引用 …]` 标注落回文字流程（OCR 文件名照样进模型），绝不判成图片去点类型图标。
