# 11 主动发起与追尾

本章解决：小漓什么时候会主动找你、怎么控制频率、状态层是什么、媒体等待怎么选。

这三个功能都会产生额外模型调用；默认都关闭，开启前先看成本。

## 1. 主动发起对话

「设置 → 主动发起对话」默认关闭。

工作方式：

1. 调度线程为每个候选会话在 `间隔下限 ~ 间隔上限`（默认 10~20 分钟）内随机取一个时间点。
2. 到期后，主循环带该会话的历史与记忆做一次**完整模型请求**。
3. 上下文末尾注入一条 user 文本：「sys：距上次聊天 X 分钟/小时/天，可以决定是否给用户发消息；不决定发消息请调用 no_reply 工具。」这条文本不写记忆。
4. 模型调 `no_reply` = 不发；输出文本或调用发送类工具 = 发出。发出后只写 assistant 历史。

护栏：

- **会话空闲**：距最后一条消息不足 `proactive_idle_minutes`（默认 10 分钟）不发起。
- **冷却**：两次主动发送之间至少 `proactive_cooldown_minutes`（默认 30 分钟）。
- **仅私聊**：默认开；群聊不主动插话。
- **候选范围**：最近 N 天有对话（默认 7 天）。
- **安静时段**：可跨午夜，例如 23:00~08:00；开启后这段时间不发起。
- **未知群聊标记**：跳过（fail-closed），不会把群当私聊搭话。
- **任务进行中/成果回传/预算耗尽/暂停**：跳过。

**不限制每日发送条数**。注意：即使模型决定不发，这次请求也消耗 token；候选会话越多、间隔越短，调用量越高。

诊断日志在 `bot.log` 的 `[主动]` 行（DEBUG），前端日志页不显示。

## 2. 主动追尾

「设置 → 主动追尾」默认关闭。

回复发出后，随机延迟 `延迟下限 ~ 延迟上限`（默认 45~90 秒）做一次很小的评估调用：

- 模型可以补一句短消息（想到什么、顺口一问），也可以不补。
- 等待期间对方又发消息 → 自动取消（不打断正在进行的对话）。
- 每聊天冷却（默认 120 分钟）、每日全局上限（默认 10 条）、仅私聊（默认开）。
- 追尾是「十次里补两三次」的克制行为，不是每条都补。

## 3. 小漓状态层

「设置 → 对话行为与跨聊天记忆 → 小漓状态层」默认关闭。

开启后：

- 时段（清晨/上午/下午/傍晚/深夜）与聊天热度在本地计算。
- 情绪/精力由每次回复后的一次小调用定量更新，每聊天约 5 分钟一次（有少量额外成本）。
- 状态作为背景注入当前时间之后，让语气自然起伏（深夜犯困、聊得投入兴奋）。
- 「状态」页可视化每个聊天的当前感受。

状态层不改变人设和记忆，只是当轮的背景。

## 4. 媒体消息等待

「设置 → 对话行为与跨聊天记忆 → 媒体消息等待」：

- **固定等待**：固定秒数（默认 10 秒），简单可靠。
- **智能静默**：纯像素检测对方是否还在连发；连续若干秒无新块就继续（通常更快，硬上限 12 秒）。

对方发图片/文件后常紧跟文字指令；等待是为了不把「图片」和「指令」拆成两次处理。

## 5. 成本和频率建议

| 功能 | 成本 | 建议 |
|---|---|---|
| 主动发起 | 每次判定一次完整调用，发不发都算 | 间隔调大、候选天数调小、只开私聊、设安静时段 |
| 主动追尾 | 每次评估一次小调用 | 延迟/冷却调大、每日上限调小 |
| 状态层 | 每次回复后一次小调用，每聊天 5 分钟节流 | 只在想要明显情绪起伏时开 |
| 媒体等待 | 无 API 成本 | 智能静默通常更快 |

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 主动发起一直不触发 | 检查总开关、候选会话是否有历史、最后一条是否是未回复的 user、空闲/冷却/安静时段是否满足；看 `bot.log` 的 `[主动]` |
| 主动发到了群里 | 确认「仅私聊」开启；群聊标记未知时会跳过；曾用名字启发式误判的会话处理一次后会落盘权威标记 |
| 追尾太频繁 | 调大冷却/延迟、调小每日上限，或关闭 |
| 状态层没变化 | 确认开关开启、引擎运行、聊过几轮；每聊天 5 分钟才更新一次 |
| 媒体等待太久 | 切「智能静默」或调小固定秒数 |
