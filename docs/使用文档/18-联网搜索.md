# 18 联网搜索

本章解决：小漓怎么联网查资料、什么时候会搜、要不要配置、有哪些限制。

## 1. 是什么

开启「设置 → 联网搜索」后，模型可以在需要时调用 `web_search` 和 `web_fetch`：

- `web_search`：搜狗 / 必应 / 百度三源并发，合并去重后返回结果。
- `web_fetch`：抓取指定网页正文，读取搜索摘要里没有的实时数据。
- 零配置、无需任何 key；搜索引擎跳转链接会自动跟随到真实目标页。

默认开启。关闭后模型看不到这两个工具，提示词里也不提，避免幻觉调用。

## 2. 什么时候会搜

由模型自己判断，例如：

- 人名/机构/学校教师查询；
- 「今天天气怎么样」——先搜再抓天气页正文；
- 商品价格、新闻、政策、比赛结果等时效信息；
- 你不知道或不确定的事实。

普通闲聊、角色扮演、已有上下文能回答的问题，通常不会搜。

如果搜索结果和问题无关，模型会换措辞重搜；搜索全挂或页面无正文时，会告知不可用或改用已有知识。

## 3. 代理设置

「设置 → 联网搜索 → 搜索代理（可选）」：

- 形式：`http://127.0.0.1:7890`，支持 http/https/socks5。
- 只影响搜索与网页抓取，**不影响模型 API**；模型 API 需要系统代理或换网络。
- 留空 = 直连。
- 当前版本的「检查更新/一键更新」也会复用这个代理设置。

## 4. 成本

- 搜索引擎和网页抓取本身不收费。
- 但工具往返会增加模型调用轮次（`VISION_TOOL_ROUNDS` 内），每次搜索/抓取的结果都会作为 tool 消息回填，消耗 token。
- 抓取长网页时 token 会明显增加；模型会尽量只读正文。

## 5. 限制

- 抓取式搜索无 SLA：搜索引擎改版、反爬、验证码都会导致失败；三源互为冗余。
- 百度自动化访问高频会触发安全验证页，通常由搜狗/必应补位。
- 搜索引擎摘要不等于实时数据；天气/股价等需要 `web_fetch` 抓正文。
- 需要登录/付费墙的页面抓不到正文。
- 搜索结果可能包含广告/无关内容，模型会自行筛选，但不保证 100% 准确。

## 6. 使用示例

- 「帮我查一下今天下午会不会下雨」→ 搜天气 → 抓天气页 → 读当前时段。
- 「XX 大学计算机学院有哪些老师」→ 搜学院教师页 → 抓正文 → 汇总。
- 「这个政策什么时候开始实施」→ 搜新闻/政府页 → 抓正文 → 回答。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 模型不搜/答旧信息 | 确认联网搜索开关开启；换更明确的问法（「查一下最新的…」） |
| 搜索失败 | 检查网络/代理；搜索引擎可能临时反爬；重试或换问法 |
| 抓到验证码/登录页 | 换来源/换问法；需要登录的页面抓不到 |
| 搜索很慢 | 三源并发 + 页面抓取需要时间；可关闭联网搜索或换网络 |
| 模型说「搜索不可用」 | 三源都失败或页面无正文；稍后重试 |
