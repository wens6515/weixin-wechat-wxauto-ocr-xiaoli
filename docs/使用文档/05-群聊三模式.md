# 05 群聊三模式

本章解决：群聊里小漓什么时候读消息、什么时候说话、全接收模式怎么工作。

## 1. 三种模式

「设置 → 群聊接收模式」：

| 模式 | 读取范围 | 怎么说话 |
|---|---|---|
| 仅 @（默认） | 只有包含 `@小漓` 的消息才处理 | 按普通回复直接发送 |
| 全接收·自主 | 群里每个可见新消息批次都进模型 | 必须调用 `send_message` / 表情包 / 语音 / 图片 / 文件等发送工具；直接输出的文字**不会**发送 |
| 全接收·@必回 | 同上，全接收 | 本批消息里有 `@小漓` 时，文本按普通回复直接发送；没有 @ 时仍必须走工具 |

`@` 的称呼来自「设置 → 小漓身份 → 微信名称」，也可以到「角色卡」页改昵称。群里 @ 的名字必须和这里一致。

## 2. 全接收模式怎么工作

- 每次检测到群里有一批**可见的新消息**，就把整批消息装配成一次带历史的模型调用（不是每条消息一次）。
- 逐条入史：群聊行首带发送者名；`@` 原样保留，不额外加「这条是点名找你」的提示。
- 媒体在记忆里记占位：`[图片]`、`[表情]`、`[文件: 名字]`。
- 新媒体照常识别：图片点击查看器捕获原图，表情按媒体矩形裁剪；不看有没有 @。
- 非 @ 的文件只登记文件名，不提取正文；之后同一发送者 @ 下指令时再按需提取。
- 模型沉默时不写任何 assistant 标记（不会出现满屏 `[已读未回复]`）；已读的位置靠每会话内存游标判重。
- 处理完（不管发没发）都会点输入框清红圈，防滞留循环。

## 3. 费用与性能

- 全接收按「每个可见新消息批次」触发一次带历史的模型调用，**费用随群活跃度上升**。
- 滚动出消息区的消息读不到——视觉通道只能看到当前屏幕上的消息。
- 群里同时有大量图片/文件时，捕获和 OCR 会更慢；失败会按 8 → 16 → 32 → 60 秒退避。
- 媒体防抖（固定/智能）同样适用于群聊，避免把图片和紧跟的文字拆开。

## 4. 群聊判定

小漓以**标题区括号人数**为权威信号判断是不是群聊。群名不含「群/集团」且标题没有人数时，可能漏判成群聊；这类会话会按私聊路径处理，回复里可能没有群聊上下文。遇到这种情况：

- 确认微信窗口标题/聊天标题区完整可见；
- 把微信窗口恢复到正常大小、不要最小化；
- 到「设置 → 小漓身份」确认昵称与 @ 名称一致。

## 5. 与主动发起/追尾的关系

- 主动发起默认「仅私聊」，不会往群里插话。
- 主动追尾默认「仅私聊」。
- 群聊标记会缓存在 `chat_meta.json`；未知会话的主动发起会跳过（fail-closed），不会靠名字猜。

## 6. 怎么测试

1. 建一个测试群，把小漓的微信号拉进去。
2. 在「设置 → 群聊接收模式」切到「全接收·自主」。
3. 群里发一条不带 @ 的消息，观察小漓是否调用 `send_message`（运行日志会显示「群聊发送」）。
4. 再发一条 `@小漓 在吗`，切到「全接收·@必回」，观察是否直接文本回复。
5. 发图片/文件，确认记忆里是占位、图片能被识别。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 群里 @ 了也不回 | 检查 @ 名称是否和「小漓身份」一致；确认群聊判定没漏；看运行日志 |
| 全接收模式下模型只输出文字、不发 | 这是设计：必须调用发送工具。检查工具是否被开关关掉 |
| 群聊越用越贵 | 全接收按批次调用；活跃群可切回「仅 @」，或关闭不必要的工具 |
| 同一批消息重复回复 | 检查游标是否被清空（AI 发过消息会清游标）；重启后会用历史做种子 |
| 群里图片/文件识别不到 | 确认消息在可见区域；滚动出视口后读不到 |
