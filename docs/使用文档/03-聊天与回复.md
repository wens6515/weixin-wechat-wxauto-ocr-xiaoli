# 03 聊天与回复

本章解决：私聊里小漓怎么回、回复节奏怎么调、智能静默怎么用、为什么有时不回。

## 1. 基本流程

对方发来消息 → 小漓检测到未读红圈 → 点击会话、读取消息 → 组装上下文调用模型 → 按回复纪律拆分发送 → 回到红圈监听。

普通文字消息从收到到回复，正常在数秒内完成；模型思考时间、网络、重试都会影响实际耗时。

私聊默认会回复。群聊默认只回复 `@小漓` 的消息，详见 [05 群聊三模式](05-群聊三模式.md)。

## 2. 回复纪律

回复风格由运行时统一注入，不随角色卡走：

- 默认只回**一条**，最多两条；只有「短叹词单独成行」这一种情况该发两条。
- 跟着对方的长度走：对方短，回复也短，不把一句话铺成一整套。
- 不迎合、不编造；不知道就说不知道。
- 禁止 emoji，只能用颜文字。
- 回复里不要出现括号旁白/动作（颜文字里的括号不算）。
- 不重复对方的话、不总结说教、不问「还有什么可以帮您」。
- 纯文本，不用 markdown/列表/代码块。
- 注意区分私聊和群聊。

角色卡只决定「她是谁」（人设、昵称、温度、模型），回复纪律对所有卡生效。

## 3. 回复节奏

「设置 → 回复节奏」：

- **段间等待**：多段回复时，下一段粘贴后停留固定秒数再发送，让对方看到「对方正在输入…」。
- **间隔抖动**：每段在上下限内随机停留，更像真人打字。与段间等待互斥：开一个会自动关另一个，也可以都关。

默认段间等待开启、2 秒；如果希望回复更快，可以关闭或调小。

## 4. 智能静默

「设置 → 对话行为与跨聊天记忆 → 智能静默」默认关闭。开启后模型可以调用 `no_reply` 决定不回复：

- 对方的半句话、自言自语、纯感叹、明显不是说给小漓听的消息，可以保持沉默。
- 静默也会点输入框标记已读，不会漏处理、不会红圈滞留。
- 拿不准时模型仍会回复；该功能滥用表现为漏回消息。

关闭时模型看不到 `no_reply` 工具，提示词里也不提，避免幻觉调用。

## 5. 暂停与启动策略

- 首页主按钮切换「运行中 / 已暂停」。
- `start_paused` 决定初始化后是否立即开始监听；新装默认「启动即暂停」。
- 暂停期间红圈不会被处理；恢复后会补处理未读会话。
- 天枢任务进行中或成果回传期间，消息监听会临时暂停，防止切窗打断发送。

## 6. 失败与重试

- API 429/5xx/网络异常会按指数退避重试，单次调用有墙钟预算，不会无限等待。
- 重试耗尽后发一条角色内的友好提示，不会把错误码原样发给对方。
- 处理失败的红圈会保留，按 8 → 16 → 32 → 60 秒退避后重试；成功清零。
- 每日消费预算耗尽时，当天不再调用模型，但会清红圈避免滞留循环，第二天自动恢复。

## 7. 按聊天覆盖

「设置 → 按聊天覆盖」可以给单个聊天单独开/关：

- 语音发送
- 联网搜索
- 任务桥
- 状态监视

未设置的聊天跟随全局。改动保存后热生效；关闭 = 该工具不声明，模型看不到。

## 8. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 完全不回复 | 引擎暂停、微信最小化、模型 Key 未配置、预算耗尽 | 看首页状态和环境卡；恢复引擎/补 Key/调预算 |
| 只回复一部分 | 智能静默、模型判断半句话、API 失败重试中 | 看运行日志；必要时关闭智能静默 |
| 回复很长/很多条 | 角色卡或模型风格、回复纪律被卡覆盖 | 检查角色卡是否把纪律写进人设；默认纪律不该被覆盖 |
| 回错人 | 窗口被手动切换、任务回传占用 | 小漓发送前会校验目标会话，确认不了会放弃；避免运行期间手动切微信 |
| 延迟很高 | 模型思考、联网搜索、重试 | 看用量页耗时；换更快的模型/关闭不必要的工具 |
