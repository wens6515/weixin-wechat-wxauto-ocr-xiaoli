# 19 角色卡与按聊天覆盖

本章解决：怎么新建/编辑/导入角色卡、怎么给不同聊天用不同人设和模型、怎么给单个聊天开关功能。

## 1. 角色卡是什么

角色卡决定小漓「是谁」：

- 名称、表情、微信昵称；
- 人格设定（system prompt）；
- 聊天模型/Provider；
- 温度、top_p、历史条数。

回复纪律（只回一条、最多两条、禁 emoji、纯文本等）由运行时统一注入，**不写在卡里**；导入别人的卡也不会把纪律带进来。

## 2. 角色卡页

导航栏「角色卡」：

- **新建**：填名称（必填）、表情、昵称、人格设定（必填）、温度/top_p/历史条数。
- **保存**：保存当前编辑的卡。
- **复制**：基于当前卡创建副本，适合做「工作版/日常版」。
- **导入/导出**：JSON 文件；导入会校验结构。
- **激活此卡**：把这张卡设为全局活跃卡；引擎运行中会热切换人设/模型/参数。
- **删除**：不可撤销；至少保留一张卡（建议）。

微信名称也可以在「设置 → 小漓身份」改；改的是活跃卡的昵称，群里的 `@` 判据会立即生效。

## 3. 给单个聊天绑定角色卡

「记忆」页选中一个会话 →「绑定角色卡」：

- 该聊天使用指定卡的人设、模型、温度、top_p、历史条数。
- 未绑定的聊天跟随全局活跃卡。
- 绑定后立即热生效；引擎未初始化时，启动后生效。

适合：不同朋友用不同人设/模型，或工作聊天用更严谨的卡。

## 4. 按聊天覆盖功能

「设置 → 按聊天覆盖」：

- 选择聊天；
- 对「语音发送 / 联网搜索 / 任务桥 / 状态监视」分别选：
  - 跟随全局（默认）
  - 开启
  - 关闭
- 「清除该聊天全部例外」恢复跟随全局。

语义：per-chat 覆盖优先于全局开关；全局关闭时，单聊「开启」仍可强制开（用于少数聊天）。关闭 = 对应工具不声明，模型看不到。

## 5. 常用组合

| 场景 | 建议 |
|---|---|
| 日常朋友聊天 | 默认小漓卡 + 便宜模型 + 仅 @ 群聊 |
| 工作/正式聊天 | 绑定严谨人设卡；关闭语音/表情包；任务桥按需 |
| 测试新模型 | 复制一张卡，改模型后绑定到测试聊天，不影响全局 |
| 多人共用 | 每个聊天绑定不同卡；注意记忆和共享池的可见性 |

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 改卡后没生效 | 确认点「激活此卡」或保存；引擎运行中才会热切换 |
| 群里 @ 不到 | 微信名称/卡昵称要和群里实际 @ 的一致 |
| 导入卡失败 | JSON 结构不对/缺必填字段；用导出的卡做模板 |
| 某个聊天不听话 | 检查是否绑定了另一张卡，或按聊天覆盖关了工具 |
| 删除卡后聊天异常 | 绑定会失效，回落到全局活跃卡；重新绑定即可 |
