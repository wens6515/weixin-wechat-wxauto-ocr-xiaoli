# 更新记录 - v2.4.0「联网搜索」

## 新增

- **联网搜索**：模型自主决定何时联网——必应/DuckDuckGo 零配置抓取链（无需任何 API key、无需任何设置），配套网页正文抓取（web_fetch），工具循环封顶 4 次补全防失控。问「今天福州天气怎么样」会先搜索再抓取天气页正文读实况数据作答，而不是只能答「去 XX 网查」
- **表情包识别**：点击媒体后以「图片和视频」查看器是否打开为图片/表情分界——真图片走 Ctrl+C 复制原图（原始分辨率），表情包裁剪消息区媒体矩形送视觉模型（动图取当前帧）；剪贴板复制失败自动落表情路线
- **小表情检测**：媒体检测阈值 80→40px，左右头像带从检测掩码结构性剔除——头像误检从「靠尺寸猜」变成「结构上不可能」，默认小黄脸表情也能被识别描述
- **用量页「清空统计」按钮**：确认后一键清空 usage.jsonl，重新计数不再需要重装

## 修复

- **表情包点击 ESC 误关微信主窗口**（严重）：旧图片路径对无查看器的表情包盲按 ESC，把微信主窗口关掉；现在 ESC 只在确认查看器窗口存在时才按（全代码库唯一 ESC 点），此类事故在结构上不可能再发生
- **群聊无 @ 红圈滞留循环**：无 @ 消息跳过回复的流程全程零点击，而微信只在会话获得交互时标记已读——红圈原样留在列表里，8 秒退避后无限循环重处理；现在跳过时点击一次输入框标记已读，红圈即清
- **空模型请求必 400**：活跃角色卡缺失被模板补建后模型名为空，视觉兜底常量带厂商前缀、聊天路无兜底，两条链路各产生一次必败请求；现在统一兜底到纯名模型
- **memory 查看滞后**：节流写盘只标记脏、无兜底时钟，稀疏对话下最后一条回复要等下一条消息才落盘（memory 查看页读到旧数据）；现在引擎轮询顶部到期检查，脏数据约 1.5 秒必落盘
- **PyAutoGUI fail-safe 拒发**：物理鼠标恰停在屏幕四角时所有输入动作被拒，回复静默丢失且失败会话反复重处理白烧 API；无人值守自动化关闭该保护（人工夺回控制权由暂停/恢复承担）

## 变更

- **默认人设内置【角色沉浸要求】**：不再在聊天首句后运行时注入——人设自带即全程生效，清空记忆、历史裁剪都不会丢
  - **升级注意**：存量用户的旧角色卡文件不含沉浸要求段落，请在角色卡编辑里补上，或删除 `cards/xiaoli.json` 后重启自动重建
- **图片处理路径统一**：删除旧预览窗截图路径，所有带图消息（纯图/图+文/文件+图）统一 Ctrl+C 原图路线
- **重置 = 彻底全新**：打包重置模式顺带清空用户目录的用量统计与定时提醒，上一轮测试残留不再带入

## 已知边界

- 抓取式搜索没有 SLA：必应/DuckDuckGo 改版或反爬升级会失效，靠双后端链 + 失败时模型自行降级兜底
- 中文多词搜索词会被必应降级成百科结果，工具描述已内置措辞校准（紧凑连写短语命中最好）

## 安装

- 下载 `xiaoli-setup-v2.4.0.exe` 双击安装（免管理员权限）
- v2.3.0 及更早版本升级：安装包直接覆盖安装，配置/记忆/角色卡全部保留
