# v2.8.1「窗口复用与日志瘦身」更新记录

## 修复

### 任务桥不再重复唤起天枢窗口

- 症状：发一条任务消息，小漓又开出一个新的天枢 CLI 窗口，任务落到新会话（上一轮的上下文没了）；有时新窗口也没认出来，任务就卡在那里
- 根因：定位 CLI 窗口时枚举「控制台类窗口」的条件太宽（类名里带 `WindowClass` 就收），实际收进的是 10 个**隐藏的系统辅助窗口**（NvContainerWindowClass、BluetoothNotificationAreaIconWindowClass、Qt…TrayIconMessageWindowClass、CrossDeviceResumeWindowClass、COMTASKSWINDOWCLASS 等）。候选列表被这些垃圾常年占满后，「终端默认标题（Windows PowerShell）+ 系统里确有 CLI 进程 + 候选唯一」这条能认出**已开着的 CLI 窗口**的判定就永远不成立，每次定位都落到「保守起见开一个新 CLI」的兜底分支
- 修复：只枚举**可见**窗口，且类名收紧到真终端类（`ConsoleWindowClass` / `CASCADIA_HOSTING_WINDOW_CLASS` / `mintty` / `ConEmu`）。实测同一台机器上候选从 10 个垃圾窗口变成「1 个真 CLI 窗口」，直接命中、不再新开
- 旧版 CLI 窗口标题是 `npm prefix`（强特征，不受此影响），新版 CLI 的标题形态变了才把这条老隐患暴露出来

## 优化

### 界面日志只留摘要，细节进日志文件

- 窗口定位类日志（如「多个候选终端窗口…fail-closed 不猜」）从界面日志降到 DEBUG：界面不再显示，完整过程仍写在本机 `bot.log`，排障时看它
- 同一批候选的重复记录只写一条（定位轮询每秒一次，原先一轮能刷十几行）
- 「已向窗口发送指令」改为一行摘要（窗口名 + 指令首行 + 字数 + 回车次数），首轮提示词这类上千字的全文只进 `bot.log`

### 首页与用量页版面调整

- 「检查更新」从独立一行移到「环境检查」面板底行右侧（与「重新检查环境」同排，状态文字右对齐贴按钮）——此前独立成行会把首页撑高，首轮提示词失败出现「重试发送首轮提示词」按钮时，「重新检查环境」会被挤到卡片文字上
- 用量页去掉「近 7 天估算消费」折线图（显示异常且参考意义有限），恢复为单张「近 7 天调用量」折线；今日估算消费等摘要卡照旧

## 升级注意

- 配置文件无破坏性变更，覆盖安装即可，配置、记忆、角色卡、任务归档全部保留
- 安装包体积与上一版持平（约 147MB）
- 若你**同时开着多个终端窗口**、且天枢 CLI 正忙（窗口标题被终端改写成「Windows PowerShell」），定位仍会保守地选择新开一个 CLI 窗口——这是有意的安全策略（宁可多开，也不把指令打进你自己开的终端）。正常情况下小漓会稳定复用同一个 CLI 窗口

## 安装

下载 `xiaoli-setup-v2.8.1.exe` 双击覆盖安装（免管理员权限），配置与记忆自动保留。
