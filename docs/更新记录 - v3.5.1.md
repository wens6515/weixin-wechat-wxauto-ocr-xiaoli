# 更新记录 · v3.5.1「主动发起修复 · 用量口径修正」

> [!WARNING]
> 本版是 **v3.5.0 的修复版**，重点修两件事：主动发起的判定请求全部被 API 拒绝（thinking 模式 400）、用量页把失败请求计入 token/缓存/消费。v3.5.0 新增的群聊全接收、远程面板、设置页自动保存等仍在持续真机实测——遇到问题请到 [Issues](https://github.com/wens6515/weixin-wechat-wxauto-ocr-xiaoli/issues) 提交（附日志与复现步骤）。需要稳定版可回退 v3.4.0；只想避开本版改动可回退 v3.5.0。

## 主动发起：100% 400 的根因与修复

测试区日志显示：应用启动后主动发起每 10~20 分钟触发一次判定，**12 小时内 136 次请求全部 400，成功发出 0 条**。失败报文统一为：

```
HTTP 400: The `reasoning_content` in the thinking mode must be passed back to the API.
```

根因是请求形状：主动发起的消息列表以 `system` 结尾（「距上次聊天 X」），且最后一条历史是 assistant。当前 thinking 模型把「末尾 system」当成**续写最后一条 assistant**，要求把那条 assistant 的 `reasoning_content` 原样传回；小漓的记忆只存 `role/content/time`，从不存思维链，于是请求在模型生成前就被拒绝。

修复：

- 「距上次聊天 X」改为 **user 文本**，内容保留 `sys：` 前缀；
- 这条文本只存在于本次判定调用，**不写记忆**；
- `call_vision_api` 移除 `system_tail` 参数与末尾 system 追加逻辑；
- 用测试区同一份历史做真实 API A/B：末尾 system → 400，末尾 user → 200。

诊断日志：

- 到期/跳过/失败/语音未确认等主动发起日志全部走 `logger.debug`，只进 `bot.log`，不进前端 `bot_run.log`；
- 前端只看得到「决定不发 / 通过工具发送 / 已发送」这类正常结果；
- 排障主动发起失败请看 `bot.log` 的 `[主动]` 行。

## 主动发起的运行安全

- **发送类工具统一校验目标会话**：`send_message` / 表情包 / 图片 / 文件在真正发送前都会 `_ensure_chat_active(chat_id)`——读标题确认、必要时切换、切完复验标题；确认不了就 fail-closed，绝不把消息/表情包贴到当前窗口里的其他聊天。
- 语音发送原本就会切会话并复验标题，保持不变。
- **群聊标记持久化**：处理会话时把标题区括号人数解析出的权威 `is_group` 写入 `chat_meta.json`（与 `memory.json` 同目录）；启动时加载，并用记忆历史做一次种子（`群聊：` 前缀 / 全接收的「发送者：正文」格式 / 名称启发式）。主动发起的候选只信这个缓存，未知会话 fail-closed——不拿「名字里有没有群」赌，避免把群当私聊主动搭话。
- **全接收批次失败指数退避**：连续失败按 8 → 16 → 32 → 60 秒退避，成功清零；失败时保留红圈、不清已读，避免每 8 秒重新捕获媒体、重打一次 API。
- **空批次不再算失败**：全接收批次里全是已见消息时，清红圈后返回「已处理」，不再落进失败退避。

## 工具循环 reasoning_content

thinking 模型在同一轮工具往返里返回 `reasoning_content` 时，回填 assistant(tool_calls) 会原样带回；响应里没有该字段就不加。它只作用于本次工具往返，不写记忆、不影响人设与后续轮次。

## 用量统计：失败调用不再污染口径

旧实现会在请求失败时用请求体估算 prompt tokens，并按「cache_hit=0 / cache_miss=全部」写库。400 请求实际上没有消耗 token，但这些估算值被 token/缓存/消费聚合当成了真实用量：

- 测试区当天 127 次主动发起 400，估算出 395,421 个 prompt tokens；当天成功调用只有 52,670 个 prompt tokens；
- 页面缓存命中率被压到 **9%**，实际成功调用是 **75.8%**（视觉主链路 78.1%）；
- 页面消费显示 **¥0.49**，实际成功调用约 **¥0.016**；
- 每日预算闸也会被失败请求误伤——127 次 400 能把当天预算「用完」，正常回复全部停掉。

修复：

- 失败调用记录 `src=fail`，**不再估算 token 写库**；只保留 kind/model/status/latency，token 与缓存留空；请求体大小只在 DEBUG 日志留一行；
- `UsageStore.summary` 的 token / cache_hit / cache_miss / reasoning / total **只累加成功调用**；calls/fail 仍统计全部尝试；
- `pricing.estimate_records` 跳过 `ok=False`，消费与每日预算只按成功调用计算；
- 近 7 天折线图排除失败行；
- 用量页文案：今日调用显示「成功 X · 失败 Y」，缓存标注「仅统计成功调用」，失败卡标注「400/401/5xx/网络」，消费旁标「失败不计费」；
- 按模型表的调用数带成功/失败 tooltip。

修正后测试区当天的数字：138 次尝试（成功 11 / 失败 127）、53.4K tokens、75.8% 缓存、¥0.016；近 30 天缓存 79.6%、消费约 ¥1.97。
