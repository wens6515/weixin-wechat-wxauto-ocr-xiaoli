# 更新记录 · v3.2.0「智能静默与跨聊天记忆」

## 智能静默：AI 自己决定要不要回

之前只要收到消息就必然回复——对方发了句「感觉」「emmm」这种**明显还没说完的半句话**，模型也立刻接话（真机现场：它自己回复「感觉啥呀，话说到一半」，判断全对却还是回了）。本版给模型一个 `no_reply` 工具（设置页「智能静默」开关，默认关）：

- 典型沉默场景写进工具描述第一位：**一个词/半句话 = 对方正在输入，等下一条一起看**；自言自语、纯感叹、不是说给你听的消息同理；「倾向回复」的适用面收窄到完整消息；
- 静默路径做了三件集成：点输入框**清红圈**（否则未读角标滞留、退避循环反复处理同一条）、对话历史记 `[已读未回复]`（下一轮模型知道这条出现过且被看过）、占位计数归零（不干扰消息边界）；
- 开关关闭 = 工具不声明、提示词不提——模型看不到这个能力，行为与旧版一致。

## 记忆页：注入与编辑

记忆页从"只能看和删"升级为可写：

- **注入**：会话详情新增「注入记忆」——重要记忆（常驻上下文，**压缩不淘汰**：手动注入的条目标 pinned，不会被压缩产出的滚动截尾挤掉）或深层存档（只进 recall 检索库，不占上下文）；
- **编辑**：重要记忆 / 近期对话 / 关键词索引 / 深层存档四类条目全部可编辑（深层按行原子重写，压缩边界不动）；
- 所有读写走运行中引擎的同一记忆存储（锁内 + 节流落盘一致），界面直接改文件会被引擎的节流写盘覆盖回来的坑不会再踩。

## 全局记忆 + 共享记忆池（默认关，设置页开启）

两个跨聊天记忆能力，边界由开关决定、开启即接受：

- **全局记忆**：`save_global_memory` 工具把「对任何聊天都成立的事实」（小漓自己的设定/经历、主人的普遍偏好、长期约定）存入独立的全局库（上限 100 条），重要记忆块与关键词命中块注入**所有**聊天的尾区（在 per-chat 注入之后——全局内容变化只作废后缀，不打碎「人设+历史」前缀缓存）；记忆页新增「🌐 全局记忆」区块，注入/编辑/删除与聊天记忆同一套操作（可审计）；
- **共享记忆池**：`recall_memory` 升级出 `scope=全部`——跨聊天检索**其他所有会话**的记忆（近期 + 重要 + 深层，含已不在近期窗口的历史会话），命中带来源聊天名，模型认为需要时像检索深层记忆一样主动拉取。工具描述里写明「主人已明确开启并授权」——真机事故：没有这句时模型拿「小鱼嘴很严」当人设推脱，从头到尾没调过一次检索工具。

## 触发器主动性：从"被问到才会"到"自己发现该改"

真机事故：每日 19:00 的问饭闹钟触发后，用户说「我每天这个时候都在回去的路上」——模型毫无反应。定位出三层叠加：lazy 档下模型看不到触发器清单、触发回递文案里没有任何触发器信息、回递链路（call_chat_ai）根本不带工具。本版四件套：

1. **回递带元数据**：触发文案带上 `[id]（daily）「内容」` 与调整提示（「发现安排该调整可用 manage_reminder 修改/取消」）——信息和动机在需要的时刻一起给到；
2. **回递走 vision 链路**：触发那一刻模型手里就有全量工具（现场改闹钟、搜索、静默都行），失败自动降级旧链路；
3. **默认档位 lazy → eager**：活跃触发器清单随请求注入尾区（清单极少变化，不伤前缀缓存），模型随时知道自己管着哪些约定；
4. **modify 放开 content**：把「问晚饭」改成「下班问候」这类内容级调整不再需要取消重建。

## 定闹钟的确认回复自然化

创建触发器（`set_reminder`）改为**工具循环内执行**：创建成功/失败都返回带 id/时间/重复（或失败原因）的回执，模型拿回执后**用自己的话**确认、致歉或再问——「记住啦，xxx 我会准时找你」这类固定客套话删除。状态监视未开启时也由模型自然转告，不再由程序发固定提示。

## 微信自带小表情识别

微信自带的 ❤ 等小表情实测只有 **33×28px**，过不了媒体检测的 40px 尺寸闸、OCR 也读不出文字——之前整条消息被静默丢弃，未读红圈滞留 8 秒退避循环反复处理（真机事故）。本版新增「空块路由」：对方有新消息但无文字无媒体时，按消息块区间直接裁剪当前帧（不点击，小表情没有可点的媒体框），走与表情包同一套 vision 角色化回复链路；识别失败也回一句清红圈，不再滞留。

## 未读红圈改固定品牌红判据

红圈检测从「红色系范围」（R≥200、G/B∈[60,130]）改为**固定品牌红 #FA5151 (250,81,81) 每通道 ±5**：真机截图逐像素实测，预览行的红心 emoji 簇中位 (244,83,104)——B 通道比品牌红高 23、±5 内 0 像素命中，彻底排除（旧范围判据对它整体放行，被当未读反复处理）；±5 内的正常渲染抖动照常检出。不做成零容差：真角标自身像素有 G/B 73~122 的描边长尾，零容差在别的机器渲染差 1 时可能整簇出局——失败模式是静默收不到消息，比误报严重。

## 表情包动作写入对话历史

表情包发送现在记进对话历史（`[发送了表情包: 文件名]`，按实际时序排在回复文字之前）——真机事故：模型连发两次同一张图，因为历史里没有它发过表情包的痕迹、它不知道自己发过。纯表情包回复同样记文件名。

## 私聊多消息合并的双层嵌套修复

私聊一轮攒下多条消息时，旧逻辑逐行加「王文生：」前缀、再被外层「私聊 - 王文生：」包一次——投给模型和记忆里的都是「私聊 - 王文生：王文生：话说 ⏎ 王文生：…」。前缀本是为群聊多发送者设计的；本版改为**只在群聊且发送者确实不止一人时**逐行带名，私聊与同一人连发直接按行拼原文。

## 已知边界

- 智能静默依赖模型判断，偶发该沉默时回了/该回时沉默属模型行为波动，可通过开关关闭；
- 共享记忆池开启后各聊天内容互相可见（含来源），隐私边界由用户开开关时自担；
- 消息窗口里"文字 + 小表情"混发时表情仍会被忽略（只处理纯表情轮），属已知取舍；
- 极偶发的「已回复消息被重读」（bot 最新回复的头像在个别帧未被检出导致边界回退）暂未处理，再次出现时单独立项。
