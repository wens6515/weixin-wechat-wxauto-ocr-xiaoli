# 更新记录 · v3.1.6「任务栏与窗口高度」

## 窗口尺寸按系统可用区域收口

前两版把窗口尺寸固定为 **1300×1610**（三区域与全部像素判据的标定尺寸）。真机遇到的问题是：**任务栏没有隐藏**的机器上，可用区域（系统已扣掉任务栏）只有 **1516** 高——1610 根本放不下，系统会把窗口截短；程序下一轮复查发现"尺寸不对"再设一次，又被截短……**每秒一次的重设还顺带把上一帧截图作废**（尺寸变了坐标系就不能用），结果是任务栏一显示出来，消息读取整体失效（用户实测：读不到消息）。

本版把目标尺寸按**工作区收口**：可用区域放不下标定尺寸时，就按可用高度/宽度收口（1.75 缩放 + 任务栏可见的机器上 = 1300×1516），窗口永远是"放得下且稳定"的尺寸，不再与系统互相拉扯。任务栏隐藏时仍是标定的 1300×1610，行为与上一版完全一致。

## 区域竖向锚点分「贴顶」「贴底」两类

窗口矮了一截后，原来纯按窗口比例算的三区域会整体错位——最要命的是**消息区底沿切进输入框**（读到的"消息"里混进输入框内容）。微信布局本身是两端分锚的：聊天记录区上沿贴聊天头部下沿（贴窗口顶），输入面板上沿贴窗口底。本版按同一口径改：

| 区域 | 上沿 | 下沿 |
|---|---|---|
| 会话列表 | 距窗口顶固定 141px | 距窗口底固定 17px |
| 消息区（聊天记录） | 距窗口顶固定 207px | 距窗口底固定 268px |
| 标题带（会话名） | 距窗口顶固定 62px | 距窗口顶固定 132px（整条贴顶） |

左右边界仍按宽度比例（窗口宽度不变时与上一版逐像素一致）。标定尺寸 1300×1610 下，这些锚点换算出的像素与上一版**完全一致**，所以窗口放得下时行为不变；只有放不下时才体现为"少读一截画布"。

## 期望头像高改为固定值

`detect_avatar_tops` 原来按 **"消息区高 ÷ 18"** 估算头像高度（在 1300×1610 上恰好算出 63px）。窗口矮一截后这个估算跟着变小，真实头像超出 1.4 倍上限被**整列丢弃** → 消息一条都读不到。头像尺寸是微信 UI 的固定元素、与窗口大小无关，改为固定 **63px**（真机标定值）。

## 输入框聚焦点距窗口底固定

发送与"标记已读"都要先点一下输入框。原来的回退算式取"窗口高 82%"处——窗口矮一截后这个点落到聊天记录上，点不到输入框。改为距窗口底固定 **149px**（输入面板中心），窗口多高都落在面板内。

## README 明确：显示缩放必须 175%

三区域与全部像素判据都是按 **1300×1610** 的微信窗口标定的，那个尺寸对应 **175% 显示缩放**下的微信界面。缩放比例不同（例如 200%），微信界面元素随之放大缩小、这些判据整体失准：**轻则读错消息，重则一条都读不到**。README 顶部警告已写明设置路径（`设置 → 系统 → 屏幕 → 缩放与布局 → 175%`，改完重启小漓）；原来的浅色模式提示撤下（浅色自 v3.1.2 起已可用）。任务栏**无需**隐藏。

## 已知边界

- 显示缩放不是 175% 时不保证读取；改完缩放请重启小漓（微信窗口会被程序调回标定尺寸）。
- 工作区**宽度**不足 1300px 时（如 1200 宽屏 + 175% 缩放），左右边界按宽度比例会跟着偏移，属降级路径。
- 跨缩放的完整自适应（把全部像素判据改成逻辑像素口径、按 DPI 缩放换算）**没有**并入本版，需要时单独立项。
