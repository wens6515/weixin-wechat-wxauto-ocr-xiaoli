# 更新记录 · v3.1.5「窗口位置与天枢安装」

## 窗口位置：从「钉死」改成「只救援」

上一版把窗口尺寸钉死之外，还把**位置**一并钉死了：初始化时记住窗口当时的位置，之后每次被移动都拉回去。真机测试当场翻车——用户启动程序时微信恰好被挪在屏幕偏左（348,0），程序就把那个位置当成"用户想要的位置"；用户想把窗口拖回右半屏，**连续 13 次被拽回**（日志里 13 条 `[窗口] … 位置 (348,0)（原 …）`）。

这个设计的根本错误是：**启动瞬间窗口在哪是任意的**（用户可能刚把窗口拖开去做别的事、可能刚被别的程序挪过），它不该被当成用户的意图。本版改成：

- **尺寸**照旧强制 **1300×1610**（三区域比例与全部像素判据都按它标定，不变）；
- **位置**完全由用户决定，屏幕范围内随便拖，程序一概不动手；
- 唯一的位置干预是**出屏救援**：窗口（部分）移出所在显示器工作区时，把它拉回完整可见。理由是点击走屏幕绝对坐标——窗口跑出屏幕后点击会落到屏幕外，切会话、点图片、发送全会失灵。

实现细节：救援按**可见内容**判定（窗口矩形含约 10px 的 DWM 不可见外沿，直接按窗口矩形判定会把"右贴边摆放"误判成越界、每次启动把窗口白推 10px）；工作区取窗口所在显示器（副屏上的窗口被拉回副屏，不会拽到主屏边缘）；窗口比工作区还高时贴工作区上沿（小屏 + 标定尺寸的必然结果）；复查节流、调整后静置、最大化先还原这些闸沿用上一版。

## 天枢：只认 CLI，一键安装改走 npm

### 一键安装不再下载源码 zip

原来的「一键安装」从 GitHub 下载 Tianshu-Tui 的**源码 zip** 解压到用户目录——包里根本没有可执行文件，而检测按「rivet 命令 / 桌面端 exe」两条判，**必然判未安装**：用户看到的现场是「安装完成 ✓」+ 卡片「未安装」，且失败原因全程被丢弃。

现在一键安装直接执行 **`npm install -g tianshu-tui`**（装出来的命令就是检测用的 `rivet`，装完即就绪），并且**失败原因原样透出**：npm 缺失 → 提示先装 Node.js；npm 非零退出 → 带 npm 输出的尾部若干行（中文 Windows 的 GBK 输出已处理）；超时 → 给出用时说明。安装没有百分比可报，卡片上会有一条"正在通过 npm 安装（约 1-3 分钟）"的提示，不再是盯着不动的进度条干等。

### 卡片不再显示「桌面端」

环境卡片同步去掉桌面端（Electron）检测：任务桥全链路（启动 CLI / 定位窗口 / 发首轮提示词 / 发 `/yes`）都走 CLI，桌面端装不装与链路无关；显示 `D:\...\tianshu-desktop.exe` 只会让人以为任务桥在用桌面端。现在天枢一项只有两种状态：`CLI(rivet) ✓` 或未安装（附一键安装指引）。旧配置里的 `tianshu_install_dir`、`tianshu_download_url` 在加载时静默丢弃。

> 窗口定位里"排除桌面端窗口"那段保留：它不是安装检测，而是防止首轮提示词 / `/yes` 误发到桌面端或诱饵窗口。

### 「我已配置完成」只发 /yes

配置引导的收尾动作原来除了发 `/yes`、关窗，还会先塞一遍**首轮提示词**（832 字的任务桥协议）。真机反馈：用户点完「我已配置完成」，看到一大段协议文本被粘贴进刚配置好的 CLI，以为程序发错了东西。

首轮提示词的归属是「引擎初始化完成时后台自动发一次」+ 首页「重发一次」按钮；而引导收尾紧接着就关窗（进程树被杀），在那里发等于发进一个马上被销毁的会话。本版把引导收尾收敛为它承诺的动作：**发 `/yes` → 关闭 CLI 窗口 → 标记引导完成**。

## 修复「绑定角色卡」从来没生效过

记忆页给某个会话绑定角色卡后，运行期始终用全局活跃卡。根因在前端确认弹窗：`selectModal` 的「确定」按钮写死返回布尔 `true`，**下拉框的选中值从未被读取**——后端把 `str(True)` = `"True"` 当卡 id 存进绑定表，投影时找不到 `cards/True.json` 就静默跳过，绑定永久失效（真机配置里存着 `{"王美晨": "True"}`）。

同一个弹窗 bug 还砸了两个功能：

- **导出记忆**：选 JSON 实际永远导出 Markdown，且点「取消」照样导出；
- **变更任务工作目录**：旧目录的「清空 / 保留」选项永远失效（永远保留），点「取消」照样改目录。

修法：带下拉的弹窗「确定」返回选中项的值、「取消」返回 `null`（三个调用方现有的取消判断自然生效），普通确认弹窗维持 `true` / `false`。另外加载配置时会**清理卡不存在的存量脏绑定**（如那条 `"True"`；卡被删除的场景一并覆盖）。

## 外观默认值调整

出厂默认改成：**卡片透明度 0% / 壁纸浓度 20% / 毛玻璃 0% / 面板浓度 100%**（此前的 50% / 12% / 100% / 50%）。

老配置做**全或无**一次性迁移：四个选项都还是旧默认（含"从未写入"）→ 视为从没调过，整体换新默认；任一被调过 → 视为有自定义，四键一个都不动（缺失的键照旧只补 `card_opacity` / `panel_opacity`，壁纸与毛玻璃保持跟随主题），用户看到的外观一点不变。

顺带说明**面板浓度到底管什么**（不少用户反馈"调了半天没反应"）：它只控制日志类表面的**底色遮罩**——首页运行日志区、日志页大框、记忆页三栏与深层存档栏；遮罩浓度 = 1 − 面板浓度，100% 即不遮罩、显示这些区域自己的底色，拉低则被页面背景色冲淡。它**不作用于卡片、弹窗、输入框和表格**。

## 已知边界

- 尺寸强制仍是**硬**的（监听期间拖动 / 最大化，最多 1 秒后拉回 1300×1610）；位置虽然自由，但**部分出屏会被拉回完整可见**——这是刻意的：出屏区域的点击必然落空；
- 屏幕本身放不下 1300×1610 时（小屏），窗口底部会超出工作区（贴顶摆放），这是标定尺寸的硬约束，不是位置逻辑的问题；
- 天枢一键安装依赖本机 Node.js 与 npm 网络（默认走你自己的 npm registry 配置）；安装失败时给出的原因来自 npm 输出本身，程序不做二次解释；
- 首轮提示词目前在**每次启动程序**时发给当时的 CLI 窗口；若引导收尾把 CLI 窗口关掉后、任务投递时又新开了 CLI 窗口，新会话是否带协议上下文取决于 rivet 自身的会话持久化行为（待实测确认，后续版本可改为"新开 CLI 时补发一轮"）。
