# 更新记录 · v3.1.3「触发器内容修复」

## 定时触发器现在会把你填的「内容」交给 AI（本版修复）

在设置页「触发器管理」里手动建的定时提醒，到点回递时**只带了时间、没带内容**——模型只看到「约定时间到了」，于是只能说「到点啦，我来提醒你咯」「时间到啦，小鱼准时来敲门咯」这类泛泛的话，跟你在「内容」栏写的「晚上和王姐姐问好、问问吃过晚饭没有」毫无关系。真机日志里一眼可见：同一件事，入队侧有内容、出话侧是空话。

```
[定时] 到期入队: 王美晨 <- 每天晚上和王姐姐问好并询问是否吃过晚饭
[定时] 已触发 -> 王美晨: 到点啦，我来提醒你咯～别忘啦 (｡･ω･｡)ﾉ♡
```

根因是回递文案只按「创建时的对话就在历史里」这条假设写：对话里让小漓创建的触发器确实成立（用户的原话就在历史里），但**界面手动创建的没有任何对话**——内容只躺在 `reminders.json` 里，从没进过模型的上下文。

修法是两条创建路径分开：

- 触发器增加**创建来源**字段：界面创建的记 `ui`，对话里创建的记 `model`；
- 回递按来源分路：`ui` 且内容非空 → 把内容作为「你之前和用户约好的事」交给模型，并附上聊天对象、要求直接说事（别提「提醒 / 定时 / 触发器」这类机制词）；`model` → 保持原样，靠创建时的对话历史；
- 旧数据不用迁移：没有来源字段的条目按「内容是否为空」判定（对话里创建的条目内容恒为空，不会误判）。已经建好的触发器不用重建，下一次触发就带内容。

## 测试

触发器链路新增三条单测：界面创建的条目必须把内容递进回递文案、对话创建的条目保持旧语义、旧数据（无来源字段）按内容回退判定；原「内容已废」的断言随之改写。

## 已知边界

- 界面创建的定时触发器，回递是**把内容当作要办的事交给模型、由它按人设说出来**，不是逐字原样发送——想要更接近原话，把内容写得口语化一些即可；
- 对话里创建的触发器仍依赖创建时的对话历史，历史滚动归档后模型可能记不准确；长跨度、要稳的提醒建议在界面里建，并在内容栏里写清。
