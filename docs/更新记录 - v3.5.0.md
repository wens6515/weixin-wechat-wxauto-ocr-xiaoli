## 群聊接收三模式

设置页新增「群聊接收模式」，三选一，只影响群聊（私聊始终照常回复）：

- **仅 @**（默认，原有行为）：只有 `@小漓` 的消息才读，其余不调模型、不回复；
- **全接收 · 自主**：群里每条新消息都进模型。模型想说话必须调用 `send_message` 等发送类工具，**直接输出的文字不会发送**；不想说就保持沉默。表情包 / 语音 / 图片 / 文件同样只能通过对应工具发出；
- **全接收 · @必回**：同样全接收，但本批消息里有 `@小漓` 时按普通回复直接发送；没有 @ 时仍必须走工具。

配套行为：

- **@ 原样保留**：全接收模式下不再剥掉 `@小漓`，也没有「这条是点名找你的」之类提示词，消息原文进模型；
- **逐条入史**：以头像锚定的消息块为单位，一条消息一条历史，群聊行首带 `发送者：正文`；图片/表情/文件在记忆里记 `[图片]` / `[表情]` / `[文件: 名字]` 占位；
- **游标判重**：模型沉默时 bot_bottom 不前移，靠每会话内存游标（文字用归一化正文、媒体用块内容指纹）剥掉已入史前缀——读到的消息全部记录、不重复记录；进程重启后从最近历史自动做种子；AI 发出消息后游标清空；
- **新媒体照常识别**：没 @ 的图片/表情也会点击捕获并送视觉模型（会短暂打开图片查看器），不看有没有 @；
- **文件策略**：没 @ 的文件只定位登记、不提取正文，后续同一发送者 @ 下指令时再按需提取；@ 的文件当场提取正文并随调用给模型看；
- **沉默不写标记**：全接收模式下模型不回复时，不写 `[已读未回复]` 之类的 assistant 条目。

## 主动发起对话

设置页新增「主动发起对话」（默认关）：

- 每个候选会话在 **10~20 分钟**随机取一个时间点做一次完整模型请求（带该会话历史、记忆、当前时间）；间隔上下限、空闲阈值、发送冷却、候选天数、仅私聊、安静时段均可配；
- 上下文末尾追加一条 **system**：「距上次聊天 X分钟/小时/天，可以决定是否给用户发消息；不决定发消息请调用 no_reply 工具。」时长带一位小数（如 `3.4小时`），超过 24 小时用天；
- 这条 system **不写记忆**；模型调 `no_reply` 时连历史都不写；真正发出消息后只写 assistant 条目；
- 判定调用声明正常全套工具（搜索 / 触发器 / 表情包 / 语音 / 图片 / 文件），不额外限制；
- **不限发送条数**（按用户要求）；安静时段默认关，开启后支持跨午夜（如 23:00~08:00）；
- 护栏：暂停 / 成果回传中 / 有天枢任务 / 超每日预算时不发起；会话空闲不足、上次主动发送未过冷却、最后一条是未回复的 user 消息时跳过；
- 调度线程只算时间、只投队列，判定与发送都在主循环——判定会执行发送类工具，daemon 线程绝不碰微信窗口。

## 远程面板

设置页「远程面板」：手机/平板浏览器经局域网访问控制面板（状态、日志、用量、触发器、暂停/恢复回复）。

- HTTP + 访问令牌（首次开启自动生成，可重置）+ SSE 推送事件；方法白名单，`quit_app` / `pick_folder` / `reveal_path` 等敏感方法不可远程调用；
- **静态资源公开、API/SSE 校验令牌**：手机首次打开页面能完整加载 CSS/JS/图片，没令牌时前端弹输入框；之前子资源请求丢掉 `?t=` 导致「裸 HTML + 巨大黑图标」的问题已修复；
- **远程模式判定改为服务端注入标记**（`window.__XL_REMOTE__`）：pywebview 本地窗口也会走本地 HTTP 服务，不能再用 `location.protocol` 判断，否则本地窗口会被误判成远程、所有 API 打到静态服务器；
- 开关改动即保存，开「局域网开放」自动开服务、关服务自动关 LAN；端口改动自动重启服务。

## 设置页自动保存

设置页 **15 个「保存」按钮全部移除**，改为字段级自动保存：

- 开关 / 下拉 / 分段按钮：改动后约 250ms 落盘；
- 文本框 / 数字：失焦或回车落盘；
- 目录：用「浏览…」选完立即保存（任务目录仍会询问旧目录内容如何处理）；
- 语音音色档案：改名、改参考路径/文本稿、启用档案、新建/删除档案、增删情绪参考都会自动保存；连续 Tab 编辑不会被整表重渲染打断；
- 成功时最多每 2 秒提示一次「已自动保存」，失败照常弹具体错误；
- 首启引导、角色卡页、模型页的保存按钮保持不变（不属于设置页字段）。

## 图片与文件发送工具

设置页「图片与文件发送」（默认关）：

- `send_image`：调用用户自配的 OpenAI images 兼容端点生成图片并发送；端点/模型为空时执行回执告知，模型自然转告；
- `send_file`：只发任务工作目录内的文件（`resolve_under_root` 路径边界，目录外/绝对路径/`..` 一律拒绝）；
- 工具按开关声明，关闭时模型看不到；工具调用在工具循环内执行，回执交模型续写。

## 启动优化与体积

- **修复启动卡约 20 秒**：远程面板开启时，`sync_remote_server()` 在 `webview.start()` 之前 `push("remote_status")`，对尚未进入 GUI 消息循环的窗口调 `evaluate_js` 会阻塞到超时。新增 GUI 就绪闸：启动前事件先入队（上限 200），`webview.start(func=on_gui_ready)` 后补发；实测远程服务启动到 GUI 就绪约 **0.4 秒**；
- 启动日志新增 `[启动] 控制面板入口` / `[启动] 配置加载完成` / `[启动] GUI 已就绪`，便于以后排查；
- PyInstaller 排除未使用的 `tkinter` / `_tkinter` / `mouseinfo`，`optimize` 提到 2；`小漓.exe` 11.2 MB → **9.5 MB**，`_internal` 268 MB → **259 MB**（cv2 / onnxruntime / rapidocr / numpy 属 OCR 必需，未动）。

## 其他修复与调整

- 群聊全接收模式下短消息游标不再被「宁可重复」规则挡住，避免模型沉默期间同一批消息反复触发模型调用；
- 语音 `always` 模式但 TTS 配置不齐时保留 `send_message` 作为可用文字通道，避免全接收模式下一个字都发不出去；
- 远程面板静态资源 401、远程开关「开了显示没开」、复制链接无地址等问题一并修复；
- README 更新记录只保留 v3.5.0 与 v3.4.0，更早版本见 Releases 页面。

## 测试与已知边界

- 测试套件共 **1114** 项：`failures=2, errors=1, skipped=2`，均为既有环境缺失（`xiaoli_app.ui` 不存在导致的 `test_trigger_manager` / `test_backdrop_themes` / `test_ui_pages`），无本版新增失败；
- 全接收模式会让群里每条新消息都触发一次带历史的模型请求，费用和频率都会上升；滚动出视口的消息读不到（视觉通道固有限制）；没 @ 的文件不读正文；
- 主动发起每次评估都会消耗 token，即使模型决定不发；默认关闭，建议按需开启；
- 本版为「功能先行」版本，部分新功能尚未完成全量真机测试：遇到问题请提交 Issue 并回退 v3.4.0。
