# v2.8.3「回复精简与拟人化」更新记录

## 优化

### 回复纪律从角色卡迁到运行时

- 背景：回复纪律（简短碎句、禁 emoji 用颜文字、区分私聊群聊等）原先**烘焙在默认角色卡的人设里**（253 字），跟着卡一起落盘。两个后果：用户在「角色卡」页编辑人设会把它整段覆盖掉（风格直接退化，且没有任何提示）；版本改进也覆盖不到**已有**的卡
- 做法：新增**运行时风格纪律块**，两条 LLM 链路（视觉单调用、聊天链路）都在人设之后作为独立 system 消息注入。角色卡只管「她是谁」（身份/性格/腔调由用户自定义），代码管「怎么说话」——改一次对所有卡立即生效。注入位置仍在稳定前缀区，不破坏缓存布局
- 迁移：首次启动把卡里烘焙的旧纪律**逐字剥离**（不模糊匹配、不动用户自定义内容），原文件备份为 `cards\<卡>.json.bak`（已存在则不覆盖，可回滚）；新装/重置后的卡模板只含人设。默认人设从 1267 字回到 1012 字

### 默认只回一条、最多两条

- 症状：对方只发一句话（如「有点想吃烤鱼了」），回复被拆成三条分别发出，每条还各说一个角度（调侃 + 提醒 + 建议）
- 根因：纪律约束的是「**句数**」（一到两句、最多三句），而模型把一套话当三句写、按换行发了三条；示例本身也给的是两到三行「你：」，等于在教它啰嗦
- 修复：口径改成**条数**——「对方一条消息，你默认只回一条，二十字左右说清就够；实在说不完才发第二条，最多两条，绝不要第三条」；并加一条「跟着对方的长度走：他说得短你就回得短，别把一句话铺成一整套（又调侃、又提醒、又建议）」。示例重做：四组里三组只给一条「你：」，唯一给两条的是短叹词那组，且注明「这是唯一该发两条的情况」
- 反面教材取自真机原始对话（烤鱼那次的三连发），逐字保留在纪律块里

### 回复长度的物理上限

- 视觉链路 `max_tokens` 从 10000 收到 400（原值约等于没有限制）
- **聊天链路此前完全没有 `max_tokens`**——定时提醒、状态监视回递、文件问答、视觉失败降级都走它，模型可以无限长。现补上同一上限，两条链路同源赋值，不做两套默认
- 配置键沿用历史名 `vision_max_tokens`（仍是唯一入口），想放宽改它即可

### 分段发送节奏与句末处理

- 段间固定 **2 秒**（首段前不等、末段后不等），模拟一条条打出来的节奏
- 段尾**单个**中文句号去掉——微信里真人很少打句号。`。。` 等连续句号、`！`、`？`、英文句点一律不动（避免误伤网址、小数、颜文字）
- 普通回复与触发器回递（定时/状态监视）共用同一套拆分与节奏，避免两处各写一遍造成漂移

### 不再以「判断用户的消息」开场

- 每轮指令从「现在判断用户的消息：是任务就调工具，否则回复」改成**收信人视角**（「有人给你发了条消息，照你平时的样子回他；只有真的需要动手做出来时才调用工具」）——任务工具的口子一点不变，但模型不再先进入「我在做分类」的元认知，那种口吻是解释腔与总结腔的来源之一
- 纯图/表情路径的指令同步改成同一口径

## 升级注意

- **首次启动会改写角色卡**：`cards\<卡>.json` 里烘焙的旧纪律被剥离（人设 1267 → 1012 字），旁边生成 `.bak` 备份，不满意可直接还原
- **回复变短是本次预期效果**：默认一条、最多两条
- **多段回复的总耗时变长**：每段之间固定等 2 秒
- 配置无破坏性变更，覆盖安装即可；历史记忆、任务目录、定时提醒、用量统计都不受影响
- 若所用模型带 reasoning（思考 token 也计入 `max_tokens`）且出现空回复，把配置里的 `vision_max_tokens` 调大即可——空回复本身有角色内兜底文案，不会静默

## 工程

- 新增 33 条测试，钉住：风格纪律块的注入位置与内容（两条链路各一条）、两条链路都带 `max_tokens`、段尾句号剥离的边界（单个剥／`。。` 不剥／`！？` 不动／英文句点不动）、段间节奏只发生在段与段之间、角色卡迁移的剥离 + 备份 + 幂等
- 全量测试 588 条通过（skipped 1，为真机微信窗口相关用例）；`xiaoli_bot.py --test` 自检 56 项通过
- 对外接口未变：占位消息计数（`N[chat]`）、`_send_text` 调用形态、触发器旁路语义全部保持
