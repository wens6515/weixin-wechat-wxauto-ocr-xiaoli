# v3.0.0「Web 前端 · 头像锚定」更新记录

> 一句话主线：界面层整体换成 **Web 前端**（pywebview + 自研 HTML/CSS/JS，代码随本版开源），消息链路按**头像**重建归属——文件卡片从「文字」判回「文件」。

## 界面：桌面端换成 Web 前端

- 界面层从 PySide6 换成 **pywebview（WebView2）承载的自研 Web 前端**：`index.html / style.css / app.js / api.js` 无构建步骤，前端经 `window.pywebview.api.*` 调后端、后端经 `window.__push` 把事件推回前端（同一套 `{ok, error}` 返回约定）
- 窗口无边框、标题栏由 HTML 自绘（拖拽 / 最小化 / 关闭到托盘），主题与壁纸库、托盘常驻、更新检查、首页实时日志、记忆页、用量页、触发器页等现有能力全部保留
- **前端代码随本版开源入库**：`xiaoli_desktop/webui/`（含字体分片与吉祥物资源）、桌面端入口 `xiaoli_web.py`、桥接层 `xiaoli_app/webbridge.py`；另附开发工具 `tools/webui_dev_server.py`（不启后端、独立起前端热调）与 `tools/smoke_webbridge.py`（桥接方法面冒烟）
- 打包入口切到 `xiaoli_web.py` 并排除 Qt/PySide6 全家桶：安装包体积 **149MB → 134MB**，启动链与引擎线程模型（`EngineThread` + `EngineBus`）不变；旧 PySide6 界面退役

## 消息归属重构：只看头像

归属判据收敛成一条（用户定案的规则），删掉此前层层降级的判据：

- **一条消息 = 一个头像**：消息归谁只看它落在哪个头像的竖直区间，`self`/对方不再由气泡颜色、x 中线、头像 y 对齐推断（气泡颜色只留作「找气泡框 / 媒体框」的结构判据）
- **分析区上沿** = 小漓最后一条消息（右侧头像最靠下那条，占位回复按 `skip_bot` 跳过）之后**下一条对方头像的上边界**——只有该上沿以下的对方内容才算本轮新消息
- **只在消息文字范围内收行**：一条消息的文字 = [该消息头像上边界, 该消息块下边界] 之间的 OCR 行，块外文字（时间/日期分隔行、小漓自己的历史回复）一律不读
- **头像区文字按几何剔除**：左右头像窄带 ∩ 头像竖直区间内的识别文字直接丢弃（头像图片上的字曾混进文件名 OCR）
- **不降级**：头像检测不到就当作该侧没有新消息，不回退任何颜色/中线判据

## 文件卡片：从「文字」判回「文件」

- 症状：对方发来文件卡片，小漓把卡片文字当普通消息处理，投递任务时**附件是空的**——任务描述里只有从文字里猜出来的文件名
- 根因：文件卡片的面板颜色与文字气泡**完全一致**，像素层把它当普通气泡；当时唯一的文件判据是 OCR 文本里的扩展名，而 OCR 会把 `xlsx` 读成 `xIsx`（`l` 读成 `I`），判据整体失效；卡片的多行文字还被图标造成的「假气泡框」拆成三条独立消息
- 新判据（用户截图定义）：**面板色与文字气泡一致 + 面板内右侧一个实心小图标** = 文件卡片；图标颜色不参与判定（Excel 绿 / Word 蓝 / PDF 红一视同仁），按「实心块」的填充率与尺寸区分图标和文字行
- 文件卡片的多行文字（文件名 / 大小）**合成一条消息**，并带 `type=file`，文件分支直接按类型触发——不再依赖 OCR 扩展名（扩展名只留作兜底）
- **防话没说完的 10 秒等待**触发条件改为「多媒体色块」：图片或文件卡片
- 文件卡片**不会**走图片点击路径：面板内部的框在像素层就不算媒体框，图片捕获（点击 → 复制/裁剪）碰不到卡片，不会误开用户文件

## 文件名定位

- 后缀被 OCR 读花（`xlsx` → `xIsx`、`x|sx`）时也能取到文件名：已知扩展名匹配不到就按「字母开头的 2~5 位后缀」再扫一遍，再走主干包含匹配（OCR 换行把文件名切两半也照常命中）
- 同名文件重复接收时，**下载时间（文件落到本机的时间）最新优先**；同一时刻再按微信重名编号 `(N)` 最大。旧规则只看 `(N)` 最大——跨月目录重收时新副本不带后缀、编号反而更小，会选中旧副本

## 升级注意

- 配置无破坏性变更，覆盖安装即可；对话记忆、任务目录、定时提醒与触发器、角色卡、用量统计都不受影响
- 界面换成 Web 前端后外观与交互与旧版一致（同一套主题与壁纸），旧的 PySide6 界面不再随包分发
- 视觉链路的行为变化：小漓自己的消息不再进入读取结果（旧实现读出来后靠上层过滤），头像区文字不再成为消息内容——这两类内容此前偶发混进消息列表，属于修掉的缺陷
