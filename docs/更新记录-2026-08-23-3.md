# 更新记录 v2.1.2（2026-08-23）

> 修复聊天主路径记忆缺失——「我上一条说的什么」场景 bot 答「没看到记录」的根因。

## 核心修复

- **聊天主路径 vision 调用不带历史记忆**——`_handle_text` 默认走 `_vision_route → call_vision_api`，而 `call_vision_api` 构造 messages 只有 system 人设 + 当前 user 消息，完全没有 `_get_history`，导致模型看不到上一条消息。现在 `call_vision_api` 增加可选参数 `chat_id`，聊天分流路径传入后注入历史（每条带 `[时间戳]` 前缀），语义与降级路径 `call_chat_ai` 逐字对齐；图片/文件描述路径不传 `chat_id`，行为不变。
- **回复时间戳前缀过滤**——`call_vision_api` 解析出回复后补时间戳前缀过滤（逐字复用 `call_chat_ai` 的正则），模型复读历史 `[ts]` 前缀时去除。
- **vision 路径上下文预算裁剪**——`call_vision_api` 注入历史后补 `fit_messages_in_budget` 预算裁剪，与 `call_chat_ai` 对称，防长历史撑爆 DeepSeek 上下文。
- **预算裁剪支持多模态**——`fit_messages_in_budget` 原对 content 做 `str()` 会把多模态块列表 repr 化成字符串、破坏图片 base64；现区分 list content（text 块按预算截断、image 块原样保留）。

## 说明

- 全量 264 单测绿（新增历史注入带时间戳前缀、无 time 字段原样注入、回复剥时间戳、多模态裁剪 RED→GREEN）。
- 记忆仍按会话名分键持久化到 memory.json；发送给 API 的历史已带时间戳前缀 + 独立「当前时间」system 消息。

## 已知边界

- OCR 会话名键漂移（visual_backend 每次轮询重新 OCR 会话名，跨轮次键可能不一致）——注入历史后若键漂移仍可能串聊天或读空记忆，属独立视觉通道问题，本次未处理。
- API 非 200 / 异常分支不写历史，导致失败轮次的 user+assistant 均不入记忆，属独立失败路径问题，本次未处理。
- 时间戳过滤正则只剥字符串开头的单个 `[YYYY-MM-DD HH:MM:SS]` 标记（无 MULTILINE），行内/多行/中文格式时间戳可能残留，与 `call_chat_ai` 现状一致。
