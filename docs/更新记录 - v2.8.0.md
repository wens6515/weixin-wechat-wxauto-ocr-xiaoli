# v2.8.0「OCR 提速与任务进度」更新记录

## 新增

### 任务桥进度回传

- 长任务处理中能看到阶段进度：天枢在关键节点（开始动手 / 大阶段切换 / 卡住或长时间等待）写 `progress.json`，小漓按节流转发到微信——不再是投递后一片沉默直到成果发回
- 三重节流防刷屏：任务开始 **前 2 分钟静默**（短任务直接等结果）、阶段文本**变化才发**、两条之间**至少 10 分钟**；进度文案就是天枢写的那句人话，不做加工
- 协议写入任务桥 README 与首轮提示词模板；旧任务目录无需改造，没有 `progress.json` 就静默跳过

### 联网搜索代理

- 设置页新增「联网搜索」分组：填代理地址（`http://127.0.0.1:7890` 形式，支持 http/https/socks5）后，联网搜索与网页抓取全部走代理；留空即直连
- **只作用于搜索与网页抓取**，不影响模型 API 调用与平台余额查询；保存即生效，无需重启
- 非法代理地址会被拒绝并保持原配置（不会误配成无法联网）

### 用量页消费折线

- 新增「近 7 天估算消费（元）」折线图，悬停看当天金额（内置价目估算，以平台余额为准）

### 首启引导语音提示

- 首次启动引导新增小贴士：在微信「设置 → 聊天」打开**语音消息自动转文字**，语音会以文字气泡显示，小漓就能直接读到语音内容

## 修复

### 文件消息定位：同名不同后缀不再串档

- 根因：文件定位只按主干名匹配，而「(N) 重名编号最大优先」的排序跨后缀通用——同名 `.7z` 自己攒出 `(2)` 编号后会压倒刚收到的 `.pdf`，把 PDF 任务导向同名压缩包
- 修复：与消息显示名**同后缀**的候选优先，`(N)/ctime` 只在同后缀组内排序；同后缀组为空（OCR 误读后缀等）时回退全部主干命中，既有容错不退化

### 任务桥归档清理按钮修复

- 设置页任务桥的「删除选中归档 / 清空归档」此前点击即报错（缺一个导入），本次修好；归档任务现在可以正常清理

### 天枢 CLI 窗口识别修复（适配新版 CLI）

- 新版天枢 CLI 的窗口标题不再是「npm prefix」：Windows Terminal 的默认标题显示运行命令行（含 `tianshu-tui`），跑工具时又自动变成「Windows PowerShell」——旧识别规则三种形态全认不出，会导致**重复开新 CLI 窗口**、任务发不到已在运行的会话
- 识别改为「CLI 进程签名 + 标题多形态 + 终端默认标题的进程证据」三级判定，新旧 CLI 通吃（`tianshu-tui` / `npm prefix` / `rivet` 三代特征都认）
- 顺带修掉三处连带硬伤：进程扫描输出按 UTF-8 解码失败（中文 Windows 实际是 GBK，导致进程证据恒失效）、桌面端排除按字样一刀切把新 CLI 标题误杀、`.rivet` 数据目录路径被误当成「CLI 在跑」

### 托盘菜单文案修复

- 托盘右键菜单的「暂停回复」现在会随运行状态实时切换为「恢复回复」，不再一直停在旧文案

## 优化

### OCR 引擎升级 + 识别链路去放大（更准、事件路径快约四成）

- 引擎换为 rapidocr 3.x（**PP-OCRv5 mobile** 模型 + onnxruntime 后端，限 2 线程防 CPU 打满）：
  - 误读修正：文件名下划线、弯引号、生僻字（群名/昵称）读对
  - 漏字补全：消息里的「嗯」「♪」「……」等不再丢
  - 噪声减少：头像幻影行、标点不一致等旧引擎顽疾消失，平均置信度提升
- 识别链路全面 **1x 原生**（2x 放大是旧引擎的小字补偿，新引擎不再需要）：
  - 红圈条带锚定 ~450ms → ~170ms；消息区读取 ~1048ms → ~715ms；标题读取 ~820ms → ~134ms
  - 完整事件路径 OCR 合计 **~1.5s → ~0.9s（快约 40%）**；0.5s 轮询节奏与 CPU 占用不变
- 模型资产随安装包分发，无需额外下载

### 工程清理（对使用无影响，提升可维护性）

- 摘除已被替代的旧运行链路（微信层独立运行模式及其配置加载/文件处理路径）、无效的协议降级分支与无引用的函数/常量
- 角色卡字段白名单清理单模型化时代前的废弃字段；配置加载彻底统一到单一事实源

## 升级注意

- 安装包体积净增约 5MB（142.5MB → 147.3MB）：新引擎的 PP-OCRv5 模型 3 个（约 21MB）随包分发，同时旧引擎自带的模型随依赖移除，两相抵消；首次安装/覆盖安装时间略长于以往
- 配置文件无破坏性变更，覆盖安装即可，配置、记忆、角色卡、任务归档全部保留
- 若任务工作目录里已有旧版 `README.md`（任务桥协议文档），进度回传协议**不会自动写进该文件**（已存在不覆盖）——新协议通过启动时的首轮提示词下发给天枢，功能不受影响；想同步文档可删除 README 后重启小漓自动重建
