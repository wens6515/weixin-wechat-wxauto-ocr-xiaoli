## 二、逐项细节（文件级）

### 波 1 正确性组（ac3af7d）

1. **单实例互斥体统一**（`xiaoli_bot.py` `acquire_single_instance`、`xiaoli_gui.py`）
   - 原缺陷：GUI 用 `XiaoLiGui_SingleInstance`、CLI 用 `XiaoLiBot_SingleInstance`，两个名字不同 → GUI 与命令行版可双开，同时抢微信窗口/发消息互相干扰。
   - 修复：统一为 `XiaoLi_SingleInstance`。

2. **微信连接重试可停止 + 上限**（`wechat_bot.py` `_connect_wx`、`xiaoli_app/engine.py`、`xiaoli_gui.py`）
   - 原缺陷：`_connect_wx` 是 `while True` 每 10 秒无限重试，无停止通道。微信没开时 GUI 点「初始化」永远卡在 `initializing`，无法取消。
   - 修复：`WeChatBot.__init__(cfg, stop_event=None, max_connect_retries=None)`；stop_event 置位立即抛异常；GUI 工厂传 `max_connect_retries=30`（约 5 分钟超时 → 引擎 error 状态可重新初始化）；CLI 不传保持无限重试（用户开着等微信启动）。睡眠分片 0.5s 保证停止响应延迟。

3. **去重集合限界**（`wechat_bot.py` `_remember_recent` / `_save_processed_id`）
   - 原缺陷：`recent_msg_ids`（内存）与 `processed_ids.json`（持久化）只增不减，长期运行膨胀。
   - 修复：新增 `_remember_recent(key)`（set + deque 顺序队列，超 5000 条丢最旧一半）；`processed_ids` 超 10000 条裁剪一半（重启时 `_seed_existing_ids` 会重新种子，去重不依赖历史）。wechat_bot 5 处 + xiaoli_bot 3 处调用点全部替换。

4. **群聊判定集中**（`wechat_bot.py` 新增模块函数 `is_group_chat(chat_name)`）
   - 行为不变（仍按名称含「群」/「集团」启发式），但收敛为单一判定点。原因：wxauto4 的 SessionElement 是 .pyd 编译模块、无源码可查群聊标志（已核实 wxautox 包未安装、wx.pyi 无 Session 类定义）。未来库暴露标志时只改一处。

5. **has_active_tasks 待回传任务修复**（`xiaoli_bot.py`，顺带发现）
   - 原缺陷：有 `result.json` 未归档的任务被 `continue` 跳过（不算活跃），与函数注释「成果未发回微信前不恢复监听」矛盾——自检 T8 一直红、回传重试窗口被打断。
   - 修复：改为 `return True`（待回传 = 活跃，归档进 sent 才不活跃）。`tests/test_card_store.py` 中固化旧行为的断言同步修正为与注释/自检一致。

### 波 2 架构组（dd56466）

6. **Controller 命令注册表重构**（`wechat_bot.py` Controller、`xiaoli_bot.py` TianshuController）
   - 原缺陷：TianshuController._listen 整段复制 Controller._listen（约 130 行 if/elif 链），新增命令靠复制粘贴。
   - 修复：命令注册表 `_commands: {name: handler}` + `HELP` dict；`_listen` 只做分发。TianshuController 用 `_register_commands()` 继承扩展（+2 命令），净删约 100 行。所有命令语义保留（含参数解析），help 动态生成。

7. **memory 节流写盘**（`wechat_bot.py` `_schedule_save_memory` / `_flush_memory`）
   - 原缺陷：`_add_history` 每条消息全量 dump memory.json（每轮对话 2-3 次）。
   - 修复：脏标记 + 距上次写盘 ≥1s 合并写（丢失窗口 ≤1s）；`run(stop_event)` 退出路径 flush；quit 命令改优雅退出（见行为变化）。

8. **CLI 切模型持久化**（`wechat_bot.py` `_persist_model_setting`）
   - 原缺陷：CLI `model xxx` / `vision-model xxx` 只改内存，重启丢失（GUI 走 config_store 会保存，行为不一致）。
   - 修复：写回 config.json 投影字段 + 活跃角色卡（GUI 投影以卡为准，写卡才能跨重启生效）。

9. **配置加载统一**（`xiaoli_bot.py` `load_merged_config`）
   - 原缺陷：CLI 走 `wechat_bot.load_config`、GUI 走 `config_store.load_config_store`，两套默认值并存（tasks_dir 默认甚至不一致）。
   - 修复：`load_merged_config` 委托 `config_store.load_config_store`（迁移/投影/写回，同一事实源）+ 补齐 task_* 默认。CLI 首次运行会创建 cards/（行为变化，见下）。自检 T1 断言同步更新。

10. **文件定位方法去重**（`wechat_bot.py` / `xiaoli_bot.py`）
    - 原缺陷：AgentBot 复制并增强父类 4 个文件定位方法，修复易漏一处。
    - 修复：`_find_user_file`（含成果排除逻辑）上提父类 WeChatBot（默认空登记表 = 不过滤）；AgentBot 删除与父类逐字相同的 `_extract_file_display_name`、`_find_file_by_display_name`（已用 AST diff 核实一致）。自检 T12/T13/T14 全部 PASS 验证继承后行为不变。

### 波 3 性能组（716da91）

11. **图片发送前压缩**（`wechat_bot.py` `_save_screenshot_compressed`）
    - 原缺陷：4K 屏幕截图 base64 原样直发视觉 API，可能 10-20MB 撑爆体积上限。
    - 修复：最长边 >2048 等比缩放（LANCZOS）+ JPEG q=88；PIL 失败兜底 PNG。`_process_image` 保存段改调此方法（.jpg 后缀）。

12. **token 估算中英加权**（`wechat_bot.py` `estimate_tokens`）
    - 原缺陷：1 字符 = 1 token，英文高估约 4 倍（100k 预算实际只用 ~25k），长英文文档被过度裁剪。
    - 修复：CJK 0.8 token/字 + ASCII 0.3 + 其余 0.6，整体仍偏保守（宁可多估不超限）。`tests/test_token_budget.py` 断言同步更新（"hello"=2、"你好世界"=4、裁剪用例消息加长到 2000 字符触发裁剪）。

13. **模型端点拼接消重**（`wechat_bot.py` `models_endpoint`）
    - 原缺陷：`fetch_models` 与 UI 测试连接各自 `url.replace("/chat/completions", "/models")`——replace 替换所有出现处，URL 中同子串出现多次时拼接错误。
    - 修复：`rsplit("/chat/completions", 1)[0] + "/models"`（只替换最后一处，不含子串原样返回），`pages.py` 测试连接共用。

### 波 4 体验组（5c21b44 + d6aca9d + 8570074）

14. **API Key 落盘 DPAPI 加密**（`xiaoli_app/config_store.py`）
    - 内存态 cfg 保持明文（引擎/UI 零改动）；`save_config` 落盘时对 `providers[].api_key` + `ai_api_key`/`vision_api_key` 加密（`dpapi:` 前缀 + base64）；`load_config_store` 读盘后解密回明文。
    - 旧明文 config 兼容（无前缀原样保留，迁移写回时自动加密）；换用户/换机解不开 → 降级空 key（界面提示重填，不崩溃）。非 Windows/无 pywin32 自动退回明文。
    - 新增 `tests/test_config_store.py` TestSecretEncryption 4 用例（落盘无明文、round-trip、旧明文兼容、解不开降空）。

15. **日志轮转 + CONFIG 延迟加载**（`wechat_bot.py`）
    - 原缺陷：模块级 `open(LOG_FILE, "w")` import 即清空日志（排障无法追溯、GUI/CLI 互清）；`CONFIG = load_config()` import 即读写 config.json。
    - 修复：RotatingFileHandler（2MB × 2 份，LogPage 增量读取自动兼容）；CONFIG 改为 `__main__` 内加载。**注意：wechat_bot.py 现在 import 零副作用。**

16. **scan_task_status 公共函数**（`xiaoli_bot.py` 模块函数 + `xiaoli_app/ui/pages.py`）
    - 原缺陷：CLI `task-status` 与 GUI 任务页各扫一遍任务目录，逻辑漂移。
    - 修复：`scan_task_status(tasks_dir) -> (entries, waiting, done, archived)`，两处共用。新增 `tests/test_task_status.py` 4 用例。

17. **群聊空内容文案对齐**（`xiaoli_bot.py` `_handle_text`）：`content = "Hello"` → `"你好呀～"`（与基类一致，空内容不再真的发 "Hello" 给 AI）。

18. **gitignore**：`bot.log.*`（日志轮转产物）。注意 gitignore **无行尾注释语法**（`bot.log.*   # 注释` 整行会被当模式导致不匹配，`8570074` 修正为注释独立行）。

## 三、行为变化（使用者/后续 AI 必读）

- **CLI 默认 tasks_dir 改变**：从 `D:\工作间\wxauto` 变为便携默认（程序目录旁 `wxauto`，`config_store.default_tasks_dir()`）。已配置用户不受影响；新机器无 D 盘也能用。
- **quit 从硬退改优雅退出**：`os._exit(0)` → `stop_event` 置位 → `bot.run` 退出（延迟约 2 秒）+ 记忆 flush。最后 1 秒内的对话不再丢失。
- **API key 落盘为密文**：`config.json` 中 key 形如 `dpapi:...`；换 Windows 用户/重装系统后 key 失效需重填（DPAPI 用户级绑定）。
- **GUI 与 CLI 互斥**：不能同时运行（提示「小漓已在运行」）。
- **日志不再每次启动清空**：轮转保留 2 份历史。
- **图片识别前自动压缩**：最长边 2048 + JPEG q=88（大图细节有损，属预期权衡）。
