# 更新记录 · v3.1.2「浅色/深色双主题」

## 浅色模式支持（本版新增）

微信界面是浅色还是深色，程序**启动时自动识别**（取会话列表区 ∪ 消息区的像素中位亮度判定），之后气泡色、气泡框、图片/文件判定都走对应的一套像素判据。在微信里切主题后自动跟随，不用重启小漓；识别不出来时按深色判据工作（不会崩，只是退化）。

### 浅色判据怎么来的

两套主题的气泡色是**镜像关系**（真机实测）：

| | 背景 | 对方气泡 | 自己气泡（绿） |
|---|---|---|---|
| 深色 | (30,30,31) | (47,47,48) —— 比背景**亮** | (53,210,141) |
| 浅色 | (250,250,250) | (238,238,240) —— 比背景**暗** | (157,242,159) |

旧版代码里写死了「对方气泡比背景亮」这条深色时代的假设，浅色下正好反向：对方气泡色会被探成图片里的纯白，接着把每个文字气泡都当成图片（文字被丢弃、消息按图片送模型）。本版把这条假设按主题拆开。

浅色下还有个更麻烦的地方：**背景 250、气泡 238、图片里的浅灰页底 242，三者只差 4~12 色阶**，靠「气泡色 ± 容差」分不开（容差大就把图片页当气泡排掉、图片被判成文字；容差小又漏气泡）。所以浅色一侧改走**结构判据**：近背景窄带（比背景暗 8~90 色距）∩ 形状闸（高 ≤200px、宽 ≤90% 幅面、宽高比 ≥0.9）∩ 实心度闸（填充率 ≥0.5），媒体排除按「已判定的面板像素」逐像素剔除。深色一侧的判据**一行未改**（真机深色帧新旧代码逐项一致），避免回归。

### 文件卡片修复

文件卡片的面板与文字气泡**同色**，判定靠面板内右侧的实心图标。修掉一个真机事故：应用内标定时消息区左缘与会话列表重叠约 3px，那条 3px 竖条是列表面板灰 (238,238,240)——与浅色气泡同色，它把近背景窄带从头粘到尾（整帧只剩一个连通域），气泡色投票因此塌掉，图标判据拿不到面板色就直接放弃，文件卡片全被判成文字消息（任务桥入口失效）。两处收口：

- 气泡取色与面板判定**共用同一份几何清洗后的掩码**（左缘按头像带切 0.12w、右缘按滚动条切 0.99w），同色竖条不再干扰；
- 图标判据**不再依赖全帧气泡色估值**：取不到时现场测面板自身的众数色当填充色；浅色下也去掉「背景色窗」排除（背景 250 与图标里的白字 255 只差 5，会把 Excel 的白 X 挖成洞、填充率掉到阈值以下）。

## 已知边界

- 浅色一侧刚落地，可能有小部分场景仍需打磨（遇到请提 issue 附日志：`_internal/bot.log` 里有 `[归位]` 诊断行，含块类型、头像锚点、面板与图标框）；
- 浅色下两个形状闸边界：**≥180px 高的浅灰整图**可能被当面板（图片读成文字），**≥6 行的超长气泡**可能被当图片（消息不丢，会以图片形式送模型）；
- v3.1.1 及更早版本只支持微信**深色**外观。
