# 更新记录 · v3.1.4「窗口与读取稳定性」

## 撤回两项用户设置：画面标定、固定窗口大小（本版）

上一版把「框选 OCR 区域」和「固定窗口大小」交给用户自己设，本版撤回——这两项都能让程序**静默地读不到消息**。

现场是这样的：用户自设区域 + 微信窗口不是标定尺寸时，对方发来的消息一直读不到，日志里每轮只有一行 `[跳过] … 窗口空`，然后 8 秒一轮地循环重试；红圈也不消（那一轮根本没读）。

根因是这套几何判据全都按**框的比例**写死：头像窄带 = 框宽 2%~14%、期望头像高 = 框高÷18、气泡 / 媒体闸同样取框的比例。它们只在「框 == 聊天区」这一前提下成立，而微信布局不是等比的——会话列表是固定像素宽、输入框是固定像素高、头像也不随窗口缩放。于是：

- 默认值只对那台标定用的 **1300×1610** 窗口成立。真机把窗口拉到 2178 宽后，聊天区左边界从 0.415 挪到 0.246，默认区域左沿就切进聊天区内部约 367px，整列对方头像被排除在区域外 → 一个都检不出 → 消息读不到；
- 用户手画的框同样会让这些常量漂移（框大一点、左沿压到会话列表、下沿切掉最新一条消息…），而标定保存时的"试读验证"只验"能不能读到字"，不验这些几何前提。

撤回的具体内容：

- 删除设置页「画面标定」卡片、标定弹窗、升级用户的一次性标定提示、首启引导第 2 步（向导改为一步完成）；
- 删除区域文件读写（`wx_ocr_region.json` 不再被读取，仓库里那份也一并移除）、区域热更新、两框标定派生函数；
- 删除「固定窗口大小」设置：设置页行、桥接方法、配置键 `wechat_window_size` 与更早的 `wechat_window_rect`（旧配置里的值在加载时静默丢弃）。

## 改为程序强制窗口尺寸

窗口尺寸不再交给用户、也不靠用户自觉：程序把它钉在标定尺寸 **1300×1610**（只看大小、不动位置）。

- 初始化连接时强制一次；
- **消息监听每轮复查**：发现被改动（拖动、最大化、贴边吸附）就调回，最多 1 秒内归位；每次分析入口（消息窗口分析 / 联合 OCR 读取）也复查一次，避免按旧尺寸算出的坐标写进记忆或用于发送；
- ±4px 容差内不折腾；调整后 1.5 秒静置期（等微信重绘，免得和用户拖动打成一串）；最大化窗口先还原再改大小；调整成功即作废上一帧截图（尺寸变了，旧帧的坐标系不能用）；
- 每次调整落一条日志：`[窗口] 微信窗口已强制为标定尺寸 1300x1610（原 2119x1288，位置未改动）`。

真机验证（本版开发时实测）：窗口 2119×1288 → 强制定位到 1300×1610（位置未动）；此时消息区裁剪正好 **747×1135**（与代码里的标定基准逐字吻合），对方侧头像一次检出 3 个。

## 微信窗口识别加固

环境卡片原来按「标题里含微信二字」扫全部窗口——用户在浏览器里开着本仓库页面时，浏览器标签标题（仓库描述里含"微信 PC 4.x"）会被当成微信窗口：卡片上把近百字的标签标题当"检测到微信窗口"显示，运行期还可能照浏览器窗口截图。

现在判据改为**进程名优先**：`Weixin.exe`（微信 4.x）/ `WeChat.exe`（3.x）精确相等（因此 `WeChatAppEx.exe` 小程序宿主自动排除），进程名读不到才退回**标题严格等于**「微信」/「WeChat」；同进程多窗口先取标题严格命中的主窗口、再按面积最大者。环境卡片与运行期**共用同一个函数**（卡片说什么运行期就认什么），详情文案也做了截断。

## 新增「微信名称」设置

群里 `@` 这个称呼认小漓，同时也是模型的自称。此前只有首启向导里能填一次，而且**填了不生效**——昵称的事实源是角色卡，向导只写配置，下一次配置加载就被卡上的旧值覆盖回去。

本版设置页新增「小漓身份」卡片：改完同时写角色卡 + 配置 + 运行中的 bot，**立即生效、不用重启**；首启向导的昵称框也真正落卡了。

## 测试

- 新增「微信窗口识别」10 条：浏览器标签不得命中、小程序宿主排除、同进程多窗口取主窗口、标题兜底只做相等、进程名组优先于面积更大的无关窗口…；
- 新增「强制窗口尺寸」13 条：容差内不动、幂等、只改大小保持左上角、最大化先还原、复查节流、调整后静置期、调整失败下轮重试、四个挂点（connect / 监听每轮 / 读取入口 / 分析入口）各自被调用；
- 新增「微信名称」7 条：写卡+配置+运行中 bot、重新加载配置后不被卡上旧值覆盖、空与超长拒绝且一处都不改、卡不存在不阻塞、向导落卡；
- 另加两条「撤回锁」用例：标定文件即便存在也不生效、相关接口（加载 / 保存 / 热更新）不得复活；
- 全量 832 条：除 3 条依赖本地 Qt 旧 UI 目录（`xiaoli_app.ui`，不在开源仓库里）的环境性用例外全部通过。

## 已知边界

- 强制尺寸是**硬**的：监听期间拖动或最大化微信窗口，最多 1 秒后会被程序拉回 1300×1610。想长期用别的窗口尺寸，本版不支持——那正是撤回用户自定义的原因；
- 窗口**位置**仍完全由你决定，程序一概不移动；
- 本版只把"用户可调"这条会自伤的路封死并强制对齐窗口，**头像检测本身的判据没改**（仍是固定色差阈值 + 期望头像高 = 区域高÷18）——判据自身的鲁棒性改进留待后续版本；
- 浅色主题下"浅色头像对白底"这种低对比组合、以及头像紧贴大图被连成一段的情况，仍可能漏检（撤回标定只是消除了"区域/尺寸错位"这一层原因）。
