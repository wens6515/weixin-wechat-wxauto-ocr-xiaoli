# 更新记录 v2.1.3（2026-08-24）

> 消息区 OCR 废弃左右分片改回单片——分片在边界切字制造碎片（真机「排」被切左半成「非」，memory 出现"非序错乱"），且分片动机不成立；另修复视觉回复时间注入、群聊重复点击、清空记忆失效、回复前缀污染。

## 核心修复

- **消息区 OCR 废弃分片，改回单片**（v2.1.2 后最重要修复）——`ocr_image_sharded` 对宽消息图做左右分片 OCR 后按 `(round(y/10), text)` 去重合并：长消息横跨分片边界时左右两片各识别出不同子串，去重失效产生重复/错位；更严重的是分片左右边界会把**整字切成两半误识**——真机「排」被切左半成「非」，消息区出现"非序错乱等问题"碎片；探针稳定复现同类碎片「丙」「马」。同时分片动机本身不成立：源码注释声称「RapidOCR limit_side_len=736(min) 会把 1508px 宽压缩到 736」，实测 `rapidocr_onnxruntime` 的 `DetPreProcess` 在 `limit_type="min"` 下是**短边不足才放大、宽图根本不压缩**；单片实测读 40+ 字超长任务指令一字不差。现彻底删除分片三函数（`ocr_image_sharded`/`_longest_overlap`/`_try_merge_shard`），消息区改回单片 `ocr_image`，超长消息完整读入、无切字碎片、无重复错位。
- **视觉回复注入当前时间 system**——`call_vision_api` 与 `call_chat_ai` 对齐，注入「当前时间」system 消息（含历史为空时），视觉模型回复可知当前时间，语义与聊天降级路径一致。
- **视觉后端自学习选中高亮 + 红圈坐标直点**——`iter_unread_sessions` 匹配红圈与会话名后把红圈中心屏幕坐标记入 `_badge_coords`；`_switch_chat` 在 OCR 会话名漏读/坐标缺失时用红圈坐标直点，根治群聊未读红圈反复点击（真机：王文生新消息 5 轮循环漏处理）。
- **设置页「清空全部记忆」真正清空**——原来 GUI 只写空文件、不动 bot 内存 `memory_db`，bot 节流写盘（`_schedule_save_memory`/`_flush_memory`）把旧记忆覆盖回磁盘导致按钮失效。现改走 `bot.clear_history` 清内存 + 落盘，bot 未就绪时回退直接清文件。
- **API 回复剥除会话装饰前缀**——新增 `strip_reply_prefix`，剥掉模型偶发复读进回复开头的 `[时间戳]`、`[私聊 - 名字]`、`[群聊 - 群名]` 标记（可叠加、循环剥到干净），剥除后再记录历史 + 发送，避免污染记忆。
